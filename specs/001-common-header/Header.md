## 사용자 시나리오 및 테스트 *(필수)*

### 사용자 스토리 1 - Header 탐색과 펼침·접힘 (우선순위: P1)

사용자는 모든 주요 화면에서 공통 Header를 통해 서비스 메뉴를 확인하고 원하는 화면이나 기능으로 이동한다.
필요에 따라 Header를 접어 콘텐츠 공간을 넓히거나 다시 펼쳐 메뉴 이름과 사용자 영역을 확인할 수 있다.

**우선순위 이유**: Header의 핵심 가치인 공통 탐색과 화면 공간 조절을 제공하는 기본 흐름이다.

**독립 검증**: 비로그인 상태에서 Header를 펼치고 접으며 로고와 네 가지 사이트 메뉴의 이동 또는 기능 실행을 확인한다.

**인수 시나리오**:

1. **상황** 사용자가 일반 페이지에 진입했고 Header가 펼쳐져 있을 때, **동작** 접기 버튼을 선택하면,
   **결과** Header가 접히고 로고·사용자 표시·사이트 메뉴가 접힌 상태 디자인으로 변경된다.
2. **상황** Header가 접혀 있을 때, **동작** 미니 로고에 마우스를 올리면, **결과** 펼치기 아이콘이 표시된다.
3. **상황** 펼치기 아이콘이 표시됐을 때, **동작** 사용자가 미니 로고를 선택하면, **결과** Header가 펼쳐진다.
4. **상황** Header가 펼쳐지거나 접혀 있을 때, **동작** 사용자가 사이트 메뉴를 선택하면, **결과** 해당 메뉴의 지정된 화면 또는 기능으로 연결된다.

---

### 사용자 스토리 2 - 비로그인 사용자 접근 (우선순위: P2)

비로그인 사용자는 펼쳐진 Header에서 로그인과 회원가입 화면으로 이동하고, 접힌 Header에서는 비로그인 상태를
나타내는 이미지를 확인한다.

**우선순위 이유**: 비로그인 사용자가 계정 기능을 발견하고 인증 흐름을 시작할 수 있어야 한다.

**독립 검증**: 비로그인 상태에서 로그인·가입하기 버튼의 목적지와 접힌 상태의 비로그인 이미지를 확인한다.

**인수 시나리오**:

1. **상황** 비로그인 사용자가 펼쳐진 Header를 보고 있을 때, **동작** 로그인 버튼을 선택하면,
   **결과** 로그인 화면으로 이동한다.
2. **상황** 비로그인 사용자가 펼쳐진 Header를 보고 있을 때, **동작** 가입하기 버튼을 선택하면,
   **결과** 회원가입 화면으로 이동한다.
3. **상황** 비로그인 사용자가 Header를 접으면, **동작** 접힘 전환이 완료됐을 때, **결과** 비로그인 상태를 나타내는 회색 꿀벌 이미지가 표시된다.

---

### 사용자 스토리 3 - 로그인 사용자 계정 접근 (우선순위: P3)

로그인 사용자는 펼쳐진 Header에서 자신의 프로필과 닉네임을 확인하고 프로필 수정 또는 로그아웃을 실행한다.
접힌 Header에서도 로그인 상태를 구분할 수 있다.

**우선순위 이유**: 로그인 사용자가 계정 상태를 인지하고 주요 계정 작업에 접근할 수 있어야 한다.

**독립 검증**: 로그인 상태에서 프로필 정보 표시, 프로필 수정 이동, 로그아웃 후 상태와 목적지를 확인한다.

**인수 시나리오**:

1. **상황** 로그인 사용자가 펼쳐진 Header를 보고 있을 때, **동작** 프로필 수정 버튼을 선택하면,
   **결과** 마이페이지로 이동한다.
2. **상황** 로그인 사용자가 펼쳐진 Header를 보고 있을 때, **동작** 로그아웃 버튼을 선택하면,
   **결과** 로그인 상태가 종료되고 비로그인 Header로 변경된 뒤 메인 화면으로 이동한다.
3. **상황** 로그인 사용자가 Header를 접으면, **동작** 접힘 전환이 완료됐을 때, **결과** 로그인 상태를 나타내는 꿀벌 이미지가 표시된다.

### 예외 상황

- `/login`, `/signup`, `/signup/complete` 화면에서는 Header가 접힌 상태로 시작한다.
- 그 밖의 적용 화면에서는 Header가 펼쳐진 상태로 시작한다.
- 실제 페이지가 아직 없는 이용약관·개인정보처리방침·고객센터는 이동 링크만 제공한다.
- 퀴즈 메뉴를 선택하면 화면 이동 대신 준비 중 안내가 표시된다.
- 로그인 정보가 없거나 로그아웃이 완료되면 사용자 영역은 비로그인 상태로 표시된다.
- 로그인 사용자의 프로필 이미지와 닉네임은 표시 전용이며 선택해도 별도 동작이 발생하지 않는다.
- 현재 위치에 해당하는 사이트 메뉴는 아이콘과 텍스트가 다른 메뉴와 구분되도록 강조된다.
- 모바일 Header 동작은 이번 기능 범위에서 제외한다.
- 명세와 디자인이 충돌하면 동작은 이 명세를 우선하며, 시각적 충돌은 임의로 결정하지 않고 보고한다.

## 요구사항 *(필수)*

### 기능 요구사항

- **FR-001**: 시스템은 기본적으로 모든 페이지에 공통 사이드 Header를 제공해야 한다.
- **FR-002**: Header는 펼침 상태와 접힘 상태를 제공하고 사용자가 두 상태 사이를 전환할 수 있어야 한다.
- **FR-003**: 일반 페이지의 Header는 펼친 상태로 시작해야 한다.
- **FR-004**: `/login`, `/signup`, `/signup/complete`의 Header는 접힌 상태로 시작해야 한다.
- **FR-005**: 펼친 Header는 일반 로고와 접기 버튼을 표시해야 한다.
- **FR-006**: 일반 로고를 선택하면 메인 화면(`/`)으로 이동해야 한다.
- **FR-007**: 접힌 Header는 미니 로고를 표시하고, 미니 로고에 마우스를 올리면 펼치기 아이콘을 표시해야 한다.
- **FR-008**: 접힌 Header의 미니 로고를 선택하면 Header가 펼쳐져야 한다.
- **FR-009**: 비로그인 상태의 펼친 Header는 로그인 버튼과 가입하기 버튼을 표시해야 한다.
- **FR-010**: 로그인 버튼은 `/login`, 가입하기 버튼은 `/signup`으로 연결되어야 한다.
- **FR-011**: 로그인 상태의 펼친 Header는 프로필 이미지, 닉네임, 프로필 수정 버튼, 로그아웃 버튼을 표시해야 한다.
- **FR-012**: 프로필 수정 버튼은 `/mypage`로 연결되어야 한다.
- **FR-013**: 로그아웃 버튼은 로그인 상태를 종료하고 Header를 비로그인 상태로 변경한 뒤 메인 화면(`/`)으로 이동시켜야 한다.
- **FR-014**: 접힌 Header는 비로그인 사용자에게 회색 꿀벌 이미지, 로그인 사용자에게 로그인 상태용 꿀벌 이미지를 표시해야 한다.
- **FR-015**: Header는 요약 노트 생성, 전체 요약 노트, 퀴즈, 마이페이지 메뉴를 제공해야 한다.
- **FR-016**: 펼친 Header는 각 사이트 메뉴의 아이콘과 이름을, 접힌 Header는 아이콘만 표시해야 한다.
- **FR-017**: 요약 노트 생성은 `/`, 전체 요약 노트는 `/summary`, 마이페이지는 `/mypage`로 연결되어야 한다.
- **FR-018**: 퀴즈 메뉴를 선택하면 준비 중 안내를 표시해야 한다.
- **FR-019**: 펼친 Header 하단에는 이용약관, 개인정보처리방침, 고객센터 링크를 표시해야 한다.
- **FR-020**: Header의 상태별 배치, 크기, 색상, 타이포그래피, 이미지 및 아이콘은 연결된 Figma 프레임과 일치해야 한다.
- **FR-021**: 로그인 사용자의 프로필 이미지와 닉네임은 표시 전용이어야 하며 선택 시 별도 동작이 발생하지 않아야 한다.
- **FR-022**: 현재 위치에 해당하는 사이트 메뉴는 아이콘과 텍스트를 함께 강조하여 다른 메뉴와 구분할 수 있어야 한다.
- **FR-023**: 모바일 화면의 Header 동작은 이번 기능 범위에 포함하지 않아야 한다.

## 성공 기준 *(필수)*

### 측정 가능한 결과

- **SC-001**: 사용자는 Header에서 원하는 주요 메뉴를 한 번 선택해 해당 화면 또는 기능에 도달할 수 있다.
- **SC-002**: 사용자는 펼침과 접힘 전환을 각각 한 번의 선택으로 완료할 수 있다.
- **SC-003**: 네 가지 조합인 비로그인·펼침, 비로그인·접힘, 로그인·펼침, 로그인·접힘 상태에서 요구된 요소가 모두 정확히 표시된다.
- **SC-004**: 지정된 세 인증 화면에서는 최초 표시 시 Header가 접혀 있고, 그 밖의 적용 화면에서는 펼쳐져 있다.
- **SC-005**: 로그인, 가입하기, 프로필 수정, 로그아웃 및 네 가지 사이트 메뉴의 지정 동작이 검증 시나리오에서 100% 성공한다.
- **SC-006**: 각 상태의 Header를 기준 Figma 프레임과 비교했을 때 주요 요소의 누락이나 잘못된 상태 표시가 없다.
- **SC-007**: 현재 위치에 해당하는 사이트 메뉴는 아이콘과 텍스트 모두에서 나머지 메뉴와 시각적으로 구분된다.

## 가정

- Header는 모든 페이지에 공통으로 노출되며, 명세에 기록된 세 인증 화면만 초기 접힘 예외로 취급한다.
- 이용약관, 개인정보처리방침, 고객센터의 실제 목적지는 후속 기능에서 확정하며 현재 범위에서는 링크 표시만 다룬다.
- 인증과 사용자 정보의 구체적인 제공 방식은 별도 명세에서 결정하며, 이 기능은 로그인 여부와 표시할 사용자 정보를 전달받는 상황을 전제로 한다.
- 기존 Header 파일은 현재 저장소에 없으므로 구현 단계에서 프로젝트가 정한 공통 Header 위치에 새로 작성한다.
- 모바일 Header는 별도 디자인과 동작 명세가 확정된 후 후속 기능으로 다룬다.
