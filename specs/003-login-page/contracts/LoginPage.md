# UI 계약: LoginPage

## 목적

`LoginPage`는 비로그인 사용자에게 이메일·비밀번호 및 소셜 로그인 진입 UI를 제공하고 입력 검증, 기본 세션 유지 안내, 요청 중 표시와 오류 안내의 책임 경계를 정의한다.

## 파일

```text
페이지: src/app/(site)/login/page.js
스타일: src/app/(site)/login/page.module.scss
경로: /login
```

## 공통 컴포넌트 계약

- Header는 `src/app/(site)/layout.js`에서 제공받으며 로그인 페이지에서 직접 렌더링하지 않는다.
- 실제 로그인 요청 중에는 `{isLoading && <Loading />}` 형태로 공통 Loading을 한 번만 표시한다.
- 로그인 이벤트 요청에는 Suspense fallback을 사용하지 않고 `loading.js`도 사용하지 않는다.
- 로그인 사용자의 접근 안내는 `CommonModal`의 `alreadyLoggedIn` 모드를 사용한다.
- 서버·서비스·네트워크 장애만 `CommonModal`의 `error` 모드로 전달한다.

## 입력 계약

| 항목 | 초기값 | 검증 | 오류 위치 |
|---|---|---|---|
| 이메일 | 빈 값 | 필수, 이메일 형식 | 로그인 영역 하단의 단일 오류 공간 |
| 비밀번호 | 빈 값 | 필수 | 로그인 영역 하단의 단일 오류 공간 |

- 입력 오류는 입력란 이탈 후 단일 오류 공간에 한 문구만 표시하고 이메일 빈 값, 이메일 형식, 비밀번호 빈 값 순서로 선택한다.
- 단일 오류 공간은 문구가 없을 때도 높이를 유지해 로그인 화면의 다른 요소가 이동하지 않게 한다.
- 비밀번호는 항상 마스킹하고 표시·숨김 기능을 제공하지 않는다.
- 로그인 단계에서 회원가입용 비밀번호 조합 규칙은 검사하지 않는다.
- 로그인 버튼은 기본 입력 검증을 통과하고 로딩 중이 아닐 때만 활성화한다.

## 요청 상태 계약

- 실제 인증 요청이 연결되면 호출 측 로그인 페이지가 Boolean `isLoading`을 소유한다.
- 요청 시작 직전에 `true`, 요청 종료 시 성공·실패와 관계없이 `false`로 변경한다.
- `isLoading=true` 동안 이메일, 비밀번호, 이메일 로그인과 소셜 로그인 버튼을 비활성화한다.
- 같은 요청을 반복 제출하거나 이메일 로그인과 소셜 로그인을 교차 실행할 수 없어야 한다.
- UI 우선 단계에서는 가짜 성공 응답, 가짜 사용자 상태, 세션 또는 메인 이동을 생성하지 않는다.

## 오류 계약

| 오류 종류 | 표시 방식 | 후속 상태 |
|---|---|---|
| 필수 입력·이메일 형식 | 로그인 영역 하단의 단일 오류 문구 | 사용자가 수정 가능 |
| 이메일 또는 비밀번호 불일치 | 폼 내부 공통 문구 | 이메일 유지, 비밀번호 초기화 |
| 자격 정보 실패로 분류된 401 | 폼 내부 공통 문구 | 공통 오류 모달 사용 안 함 |
| 서버·서비스 장애 | CommonModal `error` + 상태 번호 | CommonModal 계약에 따른 이동 |
| 네트워크 장애 | CommonModal `error` + `network` | CommonModal 계약에 따른 이동 |

서버의 원본 오류, 내부 경로, 스택과 민감 정보는 표시하지 않는다.

## 이동 계약

- 회원가입 링크는 `/signup`으로 현재 탭에서 이동한다.
- `alreadyLoggedIn`은 CommonModal이 3초 후 `/`로 이동하며 닫기 선택 시 즉시 `/`로 이동한다.
- 실제 로그인 성공 후 `/` 이동은 인증 계약이 확정된 뒤 연결한다.
- 소셜 OAuth 이동은 이번 UI 우선 범위에서 실행하지 않는다.

## 이미지 계약

| 버튼 | 이미지 |
|---|---|
| 카카오 로그인 | `/images/kakao-icon.svg` |
| 구글 로그인 | `/images/google-icon.svg` |

- 두 버튼은 아이콘과 함께 제공자 이름을 텍스트로 표시한다.
- 지정된 두 로컬 자산을 서로 바꾸거나 외부 이미지로 대체하지 않는다.

## 공통 SCSS 계약

- Input과 버튼은 별도 공통 React 컴포넌트를 만들지 않고 `src/styles/abstracts/_mixins.scss`의 공통 mixin을 사용한다.
- Input mixin은 `1px solid #ACACAC` 테두리, `5px` 모서리 반경, `0 0 10px rgba(110, 110, 110, 0.3)` 그림자와 공통 내부 정렬을 제공한다.
- 버튼 mixin은 공통 정렬·타이포그래피·모서리 스타일을 제공하고 배경색과 너비를 호출 측에서 지정할 수 있어야 한다.
- 페이지별 레이아웃, 고유 크기와 상태 스타일은 `page.module.scss`에서 추가한다.
- 이메일 입력에는 Material Symbols `person`, 비밀번호 입력에는 `lock`을 `20px` 크기로 사용하고 placeholder와 `10px` 간격을 둔다.

## 반응형 표시 계약

| 화면 | 프레임 | 그리드 | 주요 크기 |
|---|---:|---|---|
| 데스크톱 | `1320px` | 12 columns × `88px`, gutter `24px`, row `24px` | 로그인 `644px`, 입력 `534px`, 버튼 `87px`, 소셜 `56px` |
| 태블릿 | `1024px` | 8 columns, margin `32px`, gutter `24px` | 로그인 `534px`, 입력 `423px`, 버튼 `87px`, 소셜 `48px` |
| 모바일 | `480px` | 4 columns, margin `20px`, gutter `16px` | 로그인 `440px`, 입력 `325px`, 버튼 `98px`, 소셜 `48px` |

- 데스크톱·태블릿 로고는 `419px × 180px`, 모바일 로고는 `212px × 91px`를 사용한다.
- 모든 화면의 배경은 `#FBFAF9`로 통일한다.
- 모든 화면의 Input 그림자는 `0 0 10px rgba(110, 110, 110, 0.3)`로 통일한다.
- 모든 화면의 placeholder는 `16px`, Medium, `#ACACAC`로 통일한다.
- 모든 화면에서 첫 번째 입력은 `이메일`을 사용하고, 로그인 폼 아래에는 Material Symbols `info` 아이콘과 기본 세션 유지 안내를 표시한다.

## 로그인 세션 유지 계약

- 로그인 폼은 세션 저장 방식을 선택하는 체크박스나 Boolean 상태를 제공하지 않는다.
- 로그인 성공 후 Supabase의 기본 세션 갱신 정책을 사용한다.
- 로그인 폼에는 `로그아웃 전까지 로그인 상태가 유지됩니다.` 안내를 표시한다.
- Supabase Pro 세션 제한 기능은 이 계약의 범위에 포함하지 않는다.

## 접근성 계약

- 각 입력은 사용자가 인식할 수 있는 이름을 가진다.
- 오류 문구는 대응하는 입력과 연관되어 보조기술이 오류를 식별할 수 있어야 한다.
- 버튼의 비활성화 상태는 시각적으로만 표현하지 않고 실제 조작도 차단한다.
- 아이콘은 버튼 텍스트와 의미를 중복 전달하지 않도록 처리한다.
