# 빠른 검증 안내: 로그인 페이지

## 사전 조건

- 프로젝트 의존성 설치가 완료되어 있어야 한다.
- `public/images/kakao-icon.svg`와 `public/images/google-icon.svg`가 존재해야 한다.
- 공통 `Header`, `CommonModal`, `Loading` 컴포넌트가 존재해야 한다.
- 실제 Supabase 인증, OAuth, API와 세션은 이번 검증 대상이 아니다.

## 실행

```powershell
npm run dev
```

브라우저에서 `http://localhost:3000/login`을 연다.

## 검증 시나리오

### 초기 화면

1. 사이트 레이아웃의 Header가 한 번만 표시되는지 확인한다.
2. 이메일과 비밀번호가 비어 있고 기본 세션 유지 안내가 표시되는지 확인한다.
3. 초기 상태에서 입력 오류와 Loading이 표시되지 않고 CommonModal용 임시 상태나 렌더링 경계가 없는지 확인한다.
4. 로그인 버튼이 비활성화되어 있는지 확인한다.

### 입력 검증

1. 이메일과 비밀번호가 모두 빈 상태에서 입력란을 벗어나면 “이메일을 입력해 주세요.”가 표시되는지 확인한다.
2. 이메일만 비어 있으면 비밀번호 값과 관계없이 “이메일을 입력해 주세요.”가 표시되는지 확인한다.
3. 잘못된 이메일 형식을 입력하면 “올바른 이메일 형식을 입력해 주세요.”가 표시되는지 확인한다.
4. 이메일이 유효하고 비밀번호만 비어 있으면 “비밀번호를 입력해 주세요.”가 표시되는지 확인한다.
5. 단일 오류 공간에 문구가 하나만 표시되고 문구 표시·제거 시 다른 요소가 이동하지 않는지 확인한다.
6. 이메일과 비밀번호가 모두 유효할 때 오류 문구가 제거되고 로그인 버튼이 활성화되는지 확인한다.
7. 비밀번호가 항상 마스킹되고 표시·숨김 버튼이 없는지 확인한다.
8. Input 테두리 `#ACACAC`, `5px` radius, 지정 그림자와 내부 여백이 디자인과 일치하는지 확인한다.
9. 이메일에 `person`, 비밀번호에 `lock` Material Symbols가 표시되는지 확인한다.

### 공통 SCSS

1. Input과 로그인 버튼이 `_mixins.scss`의 공통 mixin을 사용하는지 확인한다.
2. 버튼 mixin이 배경색과 너비를 인자로 받아 로그인 페이지 값으로 적용되는지 확인한다.
3. Input 또는 Button 역할의 새 공통 React 컴포넌트가 생성되지 않았는지 확인한다.

### 반응형 디자인

1. `1320px`에서 로그인 영역 `644px`, 입력 영역 `534px`, 로그인 버튼 `87px`, 소셜 버튼 `56px`를 확인한다.
2. `1024px`에서 로그인 영역 `534px`, 입력 영역 `423px`, 로그인 버튼 `87px`, 소셜 버튼 `48px`를 확인한다.
3. `480px`에서 로그인 영역 `440px`, 입력 영역 `325px`, 로그인 버튼 `98px`, 소셜 버튼 `48px`를 확인한다.
4. 모바일에서 로고가 `212px × 91px`, 데스크톱·태블릿에서 `419px × 180px`인지 확인한다.
5. 모든 화면에서 배경 `#FBFAF9`, 데스크톱 기준 Input 그림자와 placeholder 스타일이 동일한지 확인한다.
6. 모든 화면에서 `이메일`과 `로그아웃 전까지 로그인 상태가 유지됩니다.` 문구가 동일한지 확인한다.

### 로그인 세션 유지 안내

1. 로그인 상태 유지 체크박스가 표시되지 않는지 확인한다.
2. Material Symbols `info` 아이콘과 안내 문구가 함께 표시되는지 확인한다.
3. 안내 문구가 `로그아웃 전까지 로그인 상태가 유지됩니다.`인지 확인한다.
4. 로그인 성공 후 별도의 선택값 없이 Supabase 기본 세션 갱신 정책을 사용하는지 확인한다.

### 소셜 로그인과 회원가입

1. 카카오 로그인 버튼에 `kakao-icon.svg`가 표시되는지 확인한다.
2. 구글 로그인 버튼에 `google-icon.svg`가 표시되는지 확인한다.
3. 두 아이콘이 서로 바뀌지 않았고 버튼 텍스트로 제공자 이름을 확인할 수 있는지 확인한다.
4. 회원가입 링크가 `/signup`을 가리키는지 확인한다.
5. UI 우선 단계에서 소셜 버튼이 가짜 OAuth 성공이나 세션을 만들지 않는지 확인한다.

### 공통 컴포넌트 경계

1. 로그인 페이지가 Header를 직접 렌더링하지 않는지 확인한다.
2. 로그인 요청 상태에는 공통 Loading만 사용하도록 구성되었는지 확인한다.
3. 로그인 이벤트 요청에 Suspense fallback과 `loading.js`가 추가되지 않았는지 확인한다.
4. 입력 오류와 자격 정보 실패는 폼 내부 오류로 유지하고 CommonModal 연결은 실제 인증 연동 단계로 남아 있는지 확인한다.
5. 가짜 로그인 성공, 사용자 상태, 세션 저장·복구와 메인 이동이 구현되지 않았는지 확인한다.

### 추후 인증 연동 시 추가 검증

1. 실제 요청 시작 시 공통 Loading이 한 번 표시되고 모든 인증 컨트롤이 비활성화되는지 확인한다.
2. 성공과 실패 모두 요청 종료 후 Loading이 제거되는지 확인한다.
3. 자격 정보 불일치가 401이어도 CommonModal이 열리지 않고 이메일 유지·비밀번호 초기화가 적용되는지 확인한다.
4. 서버·서비스·네트워크 장애만 CommonModal `error`로 전달되는지 확인한다.
5. 실제 인증 성공에만 사용자 상태, 세션과 메인 이동이 적용되는지 확인한다.

## 정적 검증

```powershell
npm run lint
```

로그인 페이지 관련 lint 오류 없이 완료되어야 한다. Production build는 페이지 통합 또는 배포 전 검증에서 실행한다.
