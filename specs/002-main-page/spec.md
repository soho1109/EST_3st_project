## 사용자 시나리오 및 테스트 *(필수)*

### 사용자 스토리 1 - 로그인 사용자의 요약 노트 생성 (우선순위: P1)

로그인 사용자는 메인 페이지에서 요약할 주제를 입력하고, 필요하면 비밀번호 보호를 설정한 뒤 요약 노트 생성을 요청한다. 생성이 완료되면 새 요약 노트를 바로 확인한다.

**우선순위 이유**: 주제를 입력해 요약 노트를 만드는 과정은 메인 페이지가 제공하는 핵심 가치다.

**독립 검증**: 로그인 상태에서 주제만 입력한 경우와 비밀번호 보호를 설정한 경우 각각 생성 요청을 완료하고, 반환된 요약 노트 화면으로 이동하는지 확인한다.

**인수 시나리오**:

1. **상황** 로그인 사용자가 유효한 주제를 입력하고 비밀번호 사용을 선택하지 않았을 때, **동작** 생성 버튼을 선택하면, **결과** 주제와 비밀번호 미사용 상태로 생성이 요청되고 완료 후 생성된 요약 노트 화면으로 이동한다.
2. **상황** 로그인 사용자가 유효한 주제를 입력하고 비밀번호 사용을 선택했을 때, **동작** 유효한 비밀번호를 입력하고 생성 버튼을 선택하면, **결과** 주제와 비밀번호 보호 정보로 생성이 요청되고 완료 후 생성된 요약 노트 화면으로 이동한다.
3. **상황** 비밀번호 사용이 선택된 상태일 때, **동작** 사용자가 선택을 해제하면, **결과** 비밀번호 입력이 비활성화되고 기존 비밀번호 값은 생성 요청에 포함되지 않는다.
4. **상황** 필수 입력값이 누락됐을 때, **동작** 사용자가 생성 버튼을 선택하면, **결과** 생성 요청이 시작되지 않고 보완해야 할 입력값을 확인할 수 있다.
5. **상황** 유효한 입력으로 생성 요청이 시작됐을 때, **동작** 요청이 진행되는 동안, **결과** 전체 입력 영역과 생성 버튼이 비활성화되고 진행 상태가 표시되어 중복 요청이 방지된다.
6. **상황** 생성 요청이 실패했을 때, **동작** 실패 결과가 반환되면, **결과** 입력값이 유지되고 입력 영역 근처에 오류 메시지가 표시되며 사용자는 다시 생성할 수 있다.

---

### 사용자 스토리 2 - 비로그인 사용자의 로그인 또는 공개 콘텐츠 접근 (우선순위: P2)

비로그인 사용자는 요약 노트 생성을 시도할 때 로그인 권장 안내를 확인하고, 로그인 화면이나 전체 요약 노트 화면으로 이동할 수 있다.

**우선순위 이유**: 생성 권한이 없는 사용자를 적절한 다음 행동으로 안내하면서 공개 콘텐츠 탐색 기회를 유지해야 한다.

**독립 검증**: 비로그인 상태에서 생성 버튼을 선택한 뒤 로그인 권장 안내의 로그인, 전체 요약 노트, 닫기 동작을 각각 확인한다.

**인수 시나리오**:

1. **상황** 비로그인 사용자가 메인 페이지에 있을 때, **동작** 생성 버튼을 선택하면, **결과** 생성 요청 없이 로그인 권장 안내가 표시된다.
2. **상황** 로그인 권장 안내가 열려 있을 때, **동작** 로그인 버튼을 선택하면, **결과** 로그인 화면으로 이동한다.
3. **상황** 로그인 권장 안내가 열려 있을 때, **동작** 전체 요약 노트 버튼을 선택하면, **결과** 전체 요약 노트 화면으로 이동한다.
4. **상황** 로그인 권장 안내가 열려 있을 때, **동작** 닫기 버튼을 선택하면, **결과** 안내가 닫히고 메인 페이지가 유지된다.

---

### 사용자 스토리 3 - 주요 기능 바로가기와 광고 확인 (우선순위: P3)

사용자는 메인 페이지의 배너와 바로가기 카드를 이용해 전체 요약 노트, 퀴즈, 마이페이지 또는 광고 콘텐츠에 접근한다.

**우선순위 이유**: 핵심 생성 흐름 외에도 서비스의 주요 영역을 발견하고 이동할 수 있어야 한다.

**독립 검증**: 각 배너와 바로가기 카드를 선택해 지정된 화면으로 이동하거나 준비 중 안내가 표시되는지 확인한다.

**인수 시나리오**:

1. **상황** 사용자가 메인 페이지에 있을 때, **동작** 전체 요약 노트 카드를 선택하면, **결과** 전체 요약 노트 화면으로 이동한다.
2. **상황** 사용자가 메인 페이지에 있을 때, **동작** 퀴즈 카드를 선택하면, **결과** 준비 중 안내가 표시된다.
3. **상황** 준비 중 안내가 열려 있을 때, **동작** 닫기 버튼을 선택하면, **결과** 안내가 닫히고 메인 페이지가 유지된다.
4. **상황** 로그인 사용자가 메인 페이지에 있을 때, **동작** 마이페이지 카드를 선택하면, **결과** 마이페이지로 이동한다.
5. **상황** 비로그인 사용자가 메인 페이지에 있을 때, **동작** 마이페이지 카드를 선택하면, **결과** 로그인 권장 안내가 표시된다.
6. **상황** 광고 목적지가 지정되어 있을 때, **동작** 사용자가 배너를 선택하면, **결과** 지정된 광고 페이지로 이동한다.

### 예외 상황

- 주제가 비어 있으면 생성 요청을 시작하지 않는다.
- 비밀번호 사용이 선택됐지만 비밀번호가 비어 있으면 생성 요청을 시작하지 않는다.
- 비밀번호 사용이 선택되지 않은 경우 입력 필드에 남아 있는 비밀번호 값이 있더라도 생성 요청에 포함하지 않는다.
- 생성 요청이 진행되는 동안 전체 입력 영역과 생성 버튼을 비활성화하고 진행 상태를 표시하여 입력 변경과 중복 요청을 방지한다.
- 생성 요청이 실패하면 입력값을 유지하고 입력 영역 근처에 오류 메시지를 표시하며 사용자가 다시 생성할 수 있게 한다.
- 광고 배너의 실제 목적지는 외부 콘텐츠 결정에 의존하며, 구현 전에 유효한 목적지가 제공되어야 한다.
- 비로그인 사용자가 마이페이지 카드를 선택하면 화면을 이동하지 않고 로그인 권장 안내를 표시한다.

## 요구사항 *(필수)*

### 기능 요구사항

- **FR-001**: 시스템은 메인 화면에 공통 Header, 요약 노트 생성 영역, 광고 배너 영역, 주요 기능 바로가기 영역을 제공해야 한다.
- **FR-002**: 요약 노트 생성 영역은 마스코트 이미지, 안내 문구, 주제 입력란, 생성 버튼, 비밀번호 사용 선택 항목, 비밀번호 입력란을 표시해야 한다.
- **FR-003**: 최초 표시 시 주제 입력값은 비어 있고, 비밀번호 사용은 선택되지 않으며, 비밀번호 입력란은 비활성화되어야 한다.
- **FR-004**: 사용자는 요약할 주제를 입력할 수 있어야 하며 주제는 생성 요청의 필수 입력값이어야 한다.
- **FR-005**: 사용자가 비밀번호 사용을 선택하면 비밀번호 입력란이 활성화되고, 선택을 해제하면 비활성화되어야 한다.
- **FR-006**: 비밀번호 사용이 선택된 경우 비밀번호는 필수 입력값이어야 한다.
- **FR-007**: 비밀번호 사용이 선택되지 않은 경우 비밀번호 값은 생성 요청에 포함되지 않아야 한다.
- **FR-008**: 로그인 사용자가 모든 필수 값을 입력하고 생성 버튼을 선택하면 주제, 비밀번호 사용 여부, 선택된 경우의 비밀번호를 포함해 요약 노트 생성을 요청해야 한다.
- **FR-009**: 요약 노트 생성이 완료되면 시스템은 생성 결과가 식별하는 요약 노트 화면으로 사용자를 이동시켜야 한다.
- **FR-010**: 비로그인 사용자가 생성 버튼을 선택하면 요약 노트 생성 요청을 보내지 않고 로그인 권장 안내를 표시해야 한다.
- **FR-011**: 로그인 권장 안내는 로그인 화면 이동, 전체 요약 노트 화면 이동, 안내 닫기 동작을 제공해야 한다.
- **FR-012**: 로그인 권장 안내의 로그인 버튼은 로그인 화면, 전체 요약 노트 버튼은 전체 요약 노트 화면으로 연결되어야 한다.
- **FR-013**: 광고 배너는 광고 이미지를 표시하고, 유효한 광고 목적지가 제공된 경우 사용자를 해당 목적지로 연결해야 한다.
- **FR-014**: 전체 요약 노트 카드는 전체 요약 노트 화면으로 연결되어야 한다.
- **FR-015**: 퀴즈 카드는 화면 이동 대신 준비 중 안내를 표시해야 한다.
- **FR-016**: 준비 중 안내는 사용자가 안내를 닫을 수 있는 동작을 제공해야 한다.
- **FR-017**: 로그인 사용자가 마이페이지 카드를 선택하면 마이페이지로 이동해야 한다.
- **FR-018**: 시스템은 주제 또는 필수 비밀번호가 누락된 경우 생성 요청을 시작하지 않아야 한다.
- **FR-019**: 주제와 비밀번호의 허용 길이 및 비밀번호 형식은 구현 전에 별도 입력 정책으로 확정되어야 한다.
- **FR-020**: 생성 요청이 진행되는 동안 시스템은 전체 입력 영역과 생성 버튼을 비활성화하고 진행 상태를 표시하여 입력 변경과 중복 요청을 방지해야 한다.
- **FR-021**: 생성 요청이 실패하면 시스템은 사용자의 입력값을 유지하고 입력 영역 근처에 오류 메시지를 표시하며 다시 생성할 수 있게 해야 한다.
- **FR-022**: 비로그인 사용자가 마이페이지 카드를 선택하면 시스템은 화면을 이동하지 않고 로그인 권장 안내를 표시해야 한다.
- **FR-023**: 메인 화면의 상태별 배치, 크기, 색상, 타이포그래피, 이미지 및 아이콘은 연결된 디자인 참조와 일치해야 한다.

### 핵심 엔티티 *(데이터를 다루는 경우에만 작성)*

- **요약 생성 요청**: 사용자가 생성하려는 주제, 비밀번호 사용 여부, 비밀번호 사용 시의 비밀번호로 구성된다.
- **요약 노트**: 생성 완료 후 사용자가 확인하는 결과물이며, 생성 결과에서 제공되는 고유 식별자로 접근한다.
- **사용자 접근 상태**: 사용자가 로그인했는지를 나타내며 생성 요청과 마이페이지 접근 가능 여부를 결정한다.
- **광고 배너**: 메인 화면에 표시되는 광고 이미지와 외부에서 제공되는 이동 목적지로 구성된다.

## 성공 기준 *(필수)*

### 측정 가능한 결과

- **SC-001**: 로그인 사용자는 유효한 주제를 입력한 뒤 두 번 이하의 선택으로 요약 노트 생성을 시작할 수 있다.
- **SC-002**: 비밀번호 미사용 및 사용 흐름 모두에서 유효한 입력으로 생성된 요약 노트 화면 이동이 검증 시나리오의 100%에서 성공한다.
- **SC-003**: 필수 값이 누락된 모든 검증 사례에서 생성 요청이 발생하지 않으며 사용자는 보완할 입력을 확인할 수 있다.
- **SC-004**: 비로그인 사용자의 생성 시도는 검증 시나리오의 100%에서 생성 요청 없이 로그인 권장 안내로 연결된다.
- **SC-005**: 로그인 권장 안내와 준비 중 안내의 모든 버튼은 각각 한 번의 선택으로 지정된 이동 또는 닫기 동작을 완료한다.
- **SC-006**: 전체 요약 노트, 퀴즈, 로그인 사용자의 마이페이지 바로가기는 검증 시나리오의 100%에서 지정된 결과를 제공한다.
- **SC-007**: 유효한 목적지가 제공된 광고 배너는 한 번의 선택으로 해당 광고 페이지에 도달하게 한다.
- **SC-008**: 기준 디자인과 비교했을 때 로그인 및 비로그인 메인 화면에서 요구된 주요 영역과 상태의 누락이 없다.
- **SC-009**: 생성 요청이 진행 중인 모든 검증 사례에서 추가 입력과 중복 요청이 차단되며, 실패한 모든 검증 사례에서 기존 입력을 잃지 않고 다시 생성할 수 있다.

## 가정

- 공통 Header의 상세 표시와 동작은 별도의 공통 Header 명세를 따른다.
- 로그인 여부는 이 기능이 사용 가능한 형태로 제공받으며, 인증 방식 자체는 이 기능 범위에서 다루지 않는다.
- 요약 생성 처리 방식과 데이터 저장 방식은 별도 서버 통신 명세에서 결정하며, 이 기능은 생성 성공 시 요약 노트 식별자를 제공받는 상황을 전제로 한다.
- 주제와 비밀번호는 필수 여부만 현재 확정됐으며, 허용 길이와 비밀번호 형식은 구현 전에 별도 입력 정책으로 확정한다.
- 광고 배너의 이미지와 실제 이동 목적지는 외부 콘텐츠로 제공되며, 목적지 결정 자체는 이 기능 범위에서 제외한다.
- 생성 요청 실패의 원인 분류와 세부 문구는 별도 통신 정책에 의존하되, 모든 실패 안내는 입력 영역 근처에 표시한다.
