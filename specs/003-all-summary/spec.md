# 기능 명세: 요약 노트 목록

**기능 브랜치**: `feature/all-summary`

**작성일**: 2026-08-06

**상태**: 초안

**입력**: 사용자 설명: `docs/specs/AllSummary.md`와 연결된 Figma 디자인을 기준으로 전체 요약 노트, 내 요약 노트, 북마크 목록 기능을 명세한다.

## 명세 및 디자인 참조

- 원본 요구사항: [`../../docs/specs/AllSummary.md`](../../docs/specs/AllSummary.md)
- 공통 의존 명세: [`../../docs/specs/Header.md`](../../docs/specs/Header.md)
- 전체 요약 노트 디자인: Figma 노드 `193:2923`
- 내 요약 노트 디자인: Figma 노드 `414:5860`
- 북마크 디자인: Figma 노드 `414:6110`
- 비로그인 펼침 Header 디자인: Figma 노드 `340:5069`
- 로그인 펼침 Header 디자인: Figma 노드 `340:5257`

## 범위

이 기능은 데스크톱 환경의 `/summary`, `/mypage/summaries`, `/mypage/bookmarks`에서 요약 노트 목록을 조회하고 검색하며, 목록 카드의 북마크 및 잠금 상태와 점진적 추가 조회를 처리하는 범위까지 포함한다. 모바일 및 태블릿 전용 동작과 디자인은 범위에서 제외한다.

## 사용자 시나리오 및 테스트 *(필수)*

### 사용자 스토리 1 - 전체 요약 노트 탐색 및 검색 (우선순위: P1)

방문자는 전체 요약 노트 목록을 최신순으로 살펴보고, AI가 생성한 주제를 입력하여 원하는 요약 노트를 즉시 찾을 수 있다.

**우선순위 이유**: 로그인 여부와 관계없이 서비스의 핵심 콘텐츠를 발견하고 상세 정보로 이동하는 기본 흐름이다.

**독립 검증**: `/summary`에 로그인 및 비로그인 상태로 각각 진입해 전체 목록, 주제 검색, 빈 검색어 초기화, 카드 상세 이동을 검증한다.

**인수 시나리오**:

1. **상황** 전체 요약 노트가 존재하고 사용자가 `/summary`에 진입했을 때, **동작** 최초 조회가 완료되면, **결과** 최신 작성일순의 전체 요약 노트 카드가 표시된다.
2. **상황** 전체 목록이 표시된 상태에서, **동작** 사용자가 검색창에 주제를 입력하면, **결과** 입력값이 바뀔 때마다 해당 주제에 맞는 검색 결과가 표시된다.
3. **상황** 검색 결과가 표시된 상태에서, **동작** 사용자가 검색어를 모두 지우거나 공백만 입력하면, **결과** 전체 목록이 다시 표시된다.
4. **상황** 검색 결과가 없을 때, **동작** 검색 요청이 완료되면, **결과** `요약 노트가 아직 생성되지 않았습니다.`라는 EmptyState가 표시된다.
5. **상황** 잠기지 않은 카드가 표시된 상태에서, **동작** 사용자가 카드를 클릭하면, **결과** 선택한 요약 노트의 `/summary/[summaryId]`로 이동한다.

### 사용자 스토리 2 - 개인 요약 및 북마크 목록 이용 (우선순위: P2)

로그인 사용자는 자신이 작성한 요약 노트와 북마크한 요약 노트를 별도 목록에서 확인하고 검색할 수 있다.

**우선순위 이유**: 개인 콘텐츠를 다시 찾고 관리하는 핵심 개인화 기능이며 인증 상태에 따른 접근 제어가 필요하다.

**독립 검증**: 로그인 상태로 두 마이페이지 경로에 접근해 목록 범위와 EmptyState를 검증하고, 비로그인 상태에서는 로그인 안내와 이동 동작을 검증한다.

**인수 시나리오**:

1. **상황** 로그인 사용자가 `/mypage/summaries`에 진입했을 때, **동작** 조회가 완료되면, **결과** 사용자가 작성한 요약 노트만 최신 작성일순으로 표시된다.
2. **상황** 로그인 사용자가 `/mypage/bookmarks`에 진입했을 때, **동작** 조회가 완료되면, **결과** 사용자가 북마크한 요약 노트만 최신 작성일순으로 표시된다.
3. **상황** 비로그인 사용자가 두 마이페이지 목록 중 하나에 진입했을 때, **동작** 접근이 감지되면, **결과** `suggestLogin` 모드의 로그인 안내 모달이 표시되고 3초 후 `/login`으로 이동한다.
4. **상황** 로그인 안내 모달이 표시된 상태에서, **동작** 사용자가 3초가 지나기 전에 모달을 닫으면, **결과** 즉시 `/login`으로 이동한다.
5. **상황** 내 요약 노트가 없을 때, **동작** 조회가 완료되면, **결과** `요약 노트가 아직 생성되지 않았습니다.`라는 EmptyState가 표시된다.
6. **상황** 북마크한 요약 노트가 없을 때, **동작** 조회가 완료되면, **결과** `북마크한 요약 노트가 없습니다.`라는 EmptyState가 표시된다.

### 사용자 스토리 3 - 카드 상태 및 점진적 목록 관리 (우선순위: P3)

사용자는 카드에서 북마크를 관리하고 잠긴 요약 노트의 비밀번호를 확인하며, 목록 끝까지 스크롤해 다음 항목을 계속 조회할 수 있다.

**우선순위 이유**: 기본 조회 이후 콘텐츠 관리와 보호된 콘텐츠 접근, 대량 목록 탐색을 완성하는 보조 흐름이다.

**독립 검증**: 북마크 성공·실패, 잠금 비밀번호 성공·실패·취소, 다음 목록 성공·실패·마지막 페이지 상태를 각각 독립적으로 검증한다.

**인수 시나리오**:

1. **상황** 로그인 사용자가 카드의 북마크 아이콘을 볼 때, **동작** 아이콘을 클릭하면, **결과** 해당 요약 노트의 북마크 등록 상태가 반대로 전환된다.
2. **상황** 북마크 목록에서 북마크된 카드가 표시될 때, **동작** 사용자가 북마크를 해제하면, **결과** 성공 즉시 해당 카드가 목록에서 제거된다.
3. **상황** 비로그인 사용자가 `/summary` 카드의 북마크 아이콘을 클릭했을 때, **동작** 클릭이 처리되면, **결과** `suggestLogin` 모드의 공통 모달이 표시된다.
4. **상황** 잠긴 카드를 클릭했을 때, **동작** 비밀번호 모달에 올바른 비밀번호를 입력하면, **결과** 모달이 닫히고 선택한 `/summary/[summaryId]`로 이동한다.
5. **상황** 비밀번호 모달에 잘못된 비밀번호를 입력했을 때, **동작** 검증이 완료되면, **결과** 모달 내부에 오류가 표시되고 재입력할 수 있다.
6. **상황** 비밀번호 모달이 표시된 상태에서, **동작** 사용자가 취소하거나 닫으면, **결과** 현재 목록에 그대로 머문다.
7. **상황** 다음 목록이 존재하고 사용자가 목록 하단에 도달했을 때, **동작** 추가 조회가 완료되면, **결과** 기존 카드 하단에 다음 카드가 중복 없이 추가된다.
8. **상황** 추가 조회가 실패했을 때, **동작** 사용자가 목록 하단의 `재시도` 버튼을 누르면, **결과** 실패했던 다음 목록 요청이 다시 실행된다.
9. **상황** 마지막 목록까지 모두 불러왔을 때, **동작** 사용자가 다시 목록 하단에 도달하면, **결과** 별도 종료 문구 없이 추가 요청이 중단된다.

### 예외 상황

- 최초 조회 또는 검색 요청이 실패하면 공통 오류 모달을 표시하고 3초 뒤 현재 페이지를 새로고침한다.
- 북마크 등록·해제 요청이 실패하면 공통 오류 모달을 표시하고 카드의 기존 북마크 상태를 유지한다.
- 추가 목록 조회가 실패해도 이미 표시된 카드는 유지하며 목록 하단에 재시도 버튼만 표시한다.
- 검색 중 입력값이 빈 문자열 또는 공백만 있는 값으로 바뀌면 검색 결과 대신 전체 목록으로 복귀한다.
- Enter 입력은 별도의 검색 동작을 실행하지 않으며 입력값 변경에 따른 검색만 수행한다.
- 로그인 이동 대기 중 안내 모달이 닫히면 남은 대기 시간을 취소하고 즉시 로그인 페이지로 이동한다.

## 요구사항 *(필수)*

### 기능 요구사항

- **FR-001**: 시스템은 `/summary`에서 로그인 여부와 관계없이 전체 요약 노트 목록을 제공해야 한다.
- **FR-002**: 시스템은 `/mypage/summaries`에서 로그인 사용자가 작성한 요약 노트만 제공해야 한다.
- **FR-003**: 시스템은 `/mypage/bookmarks`에서 로그인 사용자가 북마크한 요약 노트만 제공해야 한다.
- **FR-004**: 시스템은 세 목록을 최신 작성일순으로 표시해야 한다.
- **FR-005**: 시스템은 데스크톱 디자인에서 한 행에 네 개의 카드가 배치되는 목록을 표시해야 한다.
- **FR-006**: 각 카드는 프로필 사진, 닉네임, AI가 생성한 주제, 요약 내용, 작성일, 북마크 상태를 표시해야 한다.
- **FR-007**: 잠긴 요약 노트 카드는 잠금 상태를 구분해 표시해야 한다.
- **FR-008**: 사용자가 잠기지 않은 카드를 클릭하면 `/summary/[summaryId]`로 이동해야 한다.
- **FR-009**: 사용자가 잠긴 카드를 클릭하면 목록 위에 비밀번호 확인 모달을 표시해야 한다.
- **FR-010**: 올바른 비밀번호가 확인되면 비밀번호 모달을 닫고 선택한 `/summary/[summaryId]`로 이동해야 한다.
- **FR-011**: 잘못된 비밀번호가 입력되면 모달 내부에 오류를 표시하고 재입력을 허용해야 한다.
- **FR-012**: 사용자가 비밀번호 모달을 취소하거나 닫으면 현재 목록을 유지해야 한다.
- **FR-013**: 시스템은 검색 입력값이 변경될 때마다 AI가 생성한 주제를 대상으로 검색해야 한다.
- **FR-014**: Enter 입력은 별도의 검색 요청을 발생시키지 않아야 한다.
- **FR-015**: 검색어가 비어 있거나 공백만 있으면 전체 목록을 다시 표시해야 한다.
- **FR-016**: 검색 결과가 없으면 현재 페이지에 정의된 EmptyState 문구를 표시해야 한다.
- **FR-017**: 비로그인 사용자가 마이페이지의 두 목록 경로에 접근하면 `suggestLogin` 모드의 로그인 안내 모달을 표시해야 한다.
- **FR-018**: 로그인 안내 모달은 표시 후 3초가 지나면 `/login`으로 이동해야 한다.
- **FR-019**: 사용자가 3초 전에 로그인 안내 모달을 닫으면 즉시 `/login`으로 이동해야 한다.
- **FR-020**: 로그인 사용자는 카드의 북마크 등록과 해제를 전환할 수 있어야 한다.
- **FR-021**: 북마크 목록에서 북마크 해제에 성공하면 해당 카드를 즉시 제거해야 한다.
- **FR-022**: 비로그인 사용자가 북마크 아이콘을 클릭하면 `suggestLogin` 모드의 공통 모달을 표시해야 한다.
- **FR-023**: 북마크 요청이 실패하면 공통 오류 모달을 표시하고 기존 북마크 상태를 유지해야 한다.
- **FR-024**: 사용자가 목록 하단에 도달하고 다음 목록이 존재하면 다음 카드 묶음을 요청해 기존 목록 하단에 추가해야 한다.
- **FR-025**: 최초 조회와 추가 조회 중에는 동일한 공통 로딩 표현을 표시해야 한다.
- **FR-026**: 추가 조회에 실패하면 기존 목록을 유지하고 목록 하단에 `재시도` 버튼만 표시해야 한다.
- **FR-027**: 사용자가 재시도 버튼을 누르면 실패한 다음 목록 요청을 다시 실행해야 한다.
- **FR-028**: 마지막 목록에 도달하면 별도 종료 문구 없이 추가 요청을 중단해야 한다.
- **FR-029**: 최초 목록 조회 또는 검색 요청이 실패하면 공통 오류 모달을 표시하고 3초 뒤 현재 페이지를 새로고침해야 한다.
- **FR-030**: 시스템은 `docs/specs/Header.md`를 공통 Header 의존 명세로 적용해야 한다.
- **FR-031**: 세 페이지의 Header는 기본적으로 펼친 상태로 시작해야 한다.
- **FR-032**: `/summary`는 로그인 상태에 따라 비로그인 또는 로그인 펼침 Header를 표시해야 한다.
- **FR-033**: 마이페이지의 두 목록은 로그인 펼침 Header를 표시해야 한다.
- **FR-034**: Header에서 현재 위치에 해당하는 메뉴의 아이콘과 텍스트를 다른 메뉴와 구분되도록 강조해야 한다.
- **FR-035**: `/summary`에서는 `전체 요약 노트` 메뉴를, 마이페이지의 두 목록에서는 `마이페이지` 메뉴를 현재 위치로 강조해야 한다.
- **FR-036**: Header의 펼침·접힘 전환과 각 메뉴 동작은 `docs/specs/Header.md`를 따라야 한다.
- **FR-037**: 이 기능은 제공된 데스크톱 디자인 범위만 보장해야 한다.

### 핵심 엔티티 *(데이터를 다루는 경우에만 작성)*

- **요약 노트**: 목록과 상세 이동의 대상이며 식별자, 작성자 프로필, 닉네임, AI 생성 주제, 요약 내용, 작성일, 잠금 상태를 가진다.
- **북마크 상태**: 로그인 사용자와 요약 노트 사이의 저장 관계이며 등록 또는 미등록 상태를 가진다.
- **목록 조회 상태**: 현재 페이지 종류, 검색 주제, 불러온 카드, 다음 목록 존재 여부, 최초·추가 로딩 및 실패 상태를 나타낸다.
- **사용자 인증 상태**: 비로그인 또는 로그인 상태이며 접근 가능한 목록과 Header 사용자 영역, 북마크 동작을 결정한다.

## 성공 기준 *(필수)*

### 측정 가능한 결과

- **SC-001**: 사용자는 세 목록 페이지 진입 후 정상 네트워크 환경에서 3초 이내에 카드 목록, EmptyState 또는 오류 안내 중 하나를 확인할 수 있다.
- **SC-002**: 검색 입력값이 변경되면 정상 네트워크 환경에서 1초 이내에 해당 주제의 결과 또는 EmptyState가 표시된다.
- **SC-003**: 비로그인 사용자는 마이페이지 목록 접근 후 3초 이내에 로그인 페이지로 이동하며, 안내 모달을 먼저 닫으면 1초 이내에 이동한다.
- **SC-004**: 올바른 비밀번호를 입력한 사용자는 한 번의 확인 동작으로 선택한 잠금 요약 노트 상세 페이지에 도달할 수 있다.
- **SC-005**: 북마크 목록에서 북마크 해제에 성공한 카드는 추가 새로고침 없이 즉시 목록에서 사라진다.
- **SC-006**: 다음 목록 조회에 성공하면 기존 카드가 유지되고 새 카드가 중복 없이 한 번만 추가된다.
- **SC-007**: 최초 조회, 검색, 북마크 및 추가 조회 실패 시 각 실패 유형에 정의된 오류 안내 또는 재시도 수단이 100% 표시된다.
- **SC-008**: 각 페이지에서 현재 위치에 맞는 Header 메뉴를 사용자가 다른 메뉴와 시각적으로 구분할 수 있다.

## 가정

- 인증 상태와 사용자 식별 정보는 목록 기능이 사용할 수 있는 형태로 제공된다.
- 요약 노트 상세 페이지와 비밀번호 검증 수단은 별도 기능에서 제공된다.
- AI가 생성한 주제는 별도의 제목 필드 없이 카드의 대표 제목이자 검색 대상 역할을 한다.
- 서버는 최신 작성일순 목록과 다음 목록 존재 여부를 판단할 수 있는 정보를 제공한다.
- EmptyState의 시각적 형태는 세 페이지에서 공통으로 사용하고 문구만 페이지별로 변경한다.
- 모바일 및 태블릿 전용 배치와 Header 동작은 별도 명세에서 다룬다.
