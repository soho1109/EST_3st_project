# UI 계약: Loading

## 목적

`Loading`은 프로젝트 공통 전체 화면 진행 상태를 표시하고 뒤쪽 화면의 상호작용을 차단한다. 비동기 작업의 시작·종료와 결과는 호출 측이 관리한다.

## 컴포넌트

```text
파일: src/components/Loading.jsx
이름: Loading
스타일: src/components/Loading.module.scss
```

## Props

공개 props는 없다. 컴포넌트가 렌더링되면 항상 전체 화면 로딩을 표시한다.

## 호출 계약

### 이벤트 요청

```jsx
{
  isLoading && <Loading />;
}
```

- 호출 측은 Boolean `isLoading`을 소유한다.
- 요청 시작 시 `true`, 성공·실패와 관계없이 종료 시 `false`로 변경한다.
- 요청 중 재진입 가능한 입력과 버튼을 비활성화한다.

### 비동기 콘텐츠 렌더링

```jsx
<Suspense fallback={<Loading />}>{/* 실제로 suspend할 수 있는 콘텐츠 */}</Suspense>
```

- 실제 렌더 대기가 발생하는 콘텐츠에만 사용한다.
- 동일 작업에 이벤트 `isLoading` 표시와 Suspense fallback을 함께 연결하지 않는다.
- 동일 화면의 여러 경계가 전체 화면 Loading을 동시에 소유하지 않게 한다.

## 표시 계약

- viewport 전체를 덮는 연한 회색 배경막을 표시한다.
- 중앙에 `clear.webp`, 투명도가 순서대로 바뀌는 흰색 막대형 진행 표시와 두 줄 안내를 표시한다.
- 문구는 `잠시만 기다려주세요.`와 `로딩중입니다`로 고정한다.
- 닫기·확인·취소 버튼을 제공하지 않는다.
- 로딩 상태를 보조기술이 인식할 수 있는 상태 의미를 제공한다.

## 책임 제외

- API, 인증 또는 데이터 요청
- Promise 성공·실패 판정
- 로딩 상태 생성 또는 변경
- 오류 안내와 공통 모달 호출
- 페이지 이동과 새로고침
- 전역 로딩 카운터와 중복 탐지

## 적용 기본값

별도 명세가 다른 로딩 표현을 요구하지 않으면 전체 화면과 부분 영역 모두 이 공통 Loading을 기본으로 사용한다. 실제 페이지 연결은 각 페이지 작업 범위에서 수행한다.
