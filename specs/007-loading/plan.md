# 구현 계획: 공통 전체 화면 로딩

**브랜치**: `007-loading` | **작성일**: 2026-08-09 | **명세**: [spec.md](./spec.md)

**입력**: `/specs/007-loading/spec.md`의 기능 명세

## 요약

화면 전체를 덮는 `Loading` 공통 컴포넌트와 SCSS Module을 작성한다. `clear.webp`를 중앙에 배치하고 CSS 막대형 스피너와 두 줄 안내 문구를 표시한다. 이벤트 요청은 호출 측 Boolean `isLoading`, 렌더 중 비동기 콘텐츠는 명시적인 Suspense 경계 중 하나만 로딩 소유자로 선택한다. 경로 단위 `loading.js`, 실제 요청 처리와 전역 로딩 상태는 추가하지 않는다.

**제약 사항**: `loading.js`, 새 패키지, 상태 관리 라이브러리, 실제 API·인증·데이터 요청·이동을 추가하지 않는다. 기존 개발 메인 페이지를 수정하지 않는다.

## 구현 설계

### 컴포넌트 표시 계약

- `Loading`은 호출되면 항상 전체 화면 로딩을 렌더링하며 공개 props를 요구하지 않는다.
- 이벤트 요청 호출자는 `isLoading && <Loading />`처럼 표시 여부를 소유하고 성공·실패와 관계없이 작업 종료 시 상태를 해제한다.
- 비동기 렌더링 호출자는 실제로 suspend하는 콘텐츠의 단일 상위 경계에 `fallback={<Loading />}`을 제공한다.
- 같은 작업에서 위 두 방식을 함께 사용하지 않으며 Loading 자체는 중복을 탐지하거나 전역 카운터를 관리하지 않는다.

### 디자인과 애니메이션

- 고정 위치 오버레이를 viewport 전체에 배치하고 기존 공통 모달보다 로딩이 앞에 표시될 수 있는 명확한 stacking level을 사용한다.
- 중앙 표시 영역에 `next/image`로 `/images/clear.webp`를 배치하며 안내 문구가 의미를 전달하므로 이미지는 장식 이미지로 처리한다.
- 흰색 막대 12개를 원형으로 배치하고 CSS keyframes와 순차 지연으로 각 막대의 투명도가 차례대로 바뀌게 한다. 정확한 크기·간격·속도는 첨부 디자인과 수동 비교로 조정한다.
- `prefers-reduced-motion: reduce`에서는 투명도 변화 주기를 현저히 늘리되 정적 이미지와 안내 문구만으로도 로딩 상태를 이해할 수 있게 유지한다.
- 안내 문구는 디자인대로 두 줄을 분리하여 표시한다.

### 상호작용과 접근성

- 오버레이가 포인터 입력을 가로채고 호출 화면은 `isLoading` 동안 재진입 가능한 컨트롤을 비활성화한다.
- 로딩 영역은 상태 역할과 live 안내를 제공하고 전체 화면이 처리 중임을 보조기술에 전달한다.
- 개발 확인에서는 포인터 클릭뿐 아니라 Tab 및 키보드 입력으로 뒤쪽 컨트롤을 실행할 수 없는지 검증한다.
- Loading은 닫기·확인·취소·이동 동작과 포커스 가능한 조작 요소를 제공하지 않는다.

### 적용 범위

- 로그인, 회원가입, 생성·수정·삭제·제출 요청은 호출 측 `isLoading`을 우선한다.
- `/summary`, `/mypage/summaries`, `/mypage/bookmarks`의 최초·검색·추가 조회는 동일한 Loading 표현과 단일 소유권 규칙을 적용한다.
- 별도 명세가 다른 로딩 표현을 요구하지 않는 한 부분 영역 데이터 대기에도 이 전체 화면 Loading을 사용한다.
- 실제 페이지 적용은 각 페이지의 후속 구현 범위이며 이번 구현은 공통 컴포넌트와 개발 확인 화면까지만 수행한다.

## 구현 순서

1. `Loading.jsx`에 오버레이, 프로필 이미지, 12개 막대형 스피너와 두 줄 상태 문구를 구성한다.
2. `Loading.module.scss`에 전체 화면 차단, 중앙 정렬, 막대 배치·순차 투명도 변화와 모션 감소 스타일을 작성한다.
3. `/dev/loading` 개발 확인 화면에서 `isLoading` 토글과 뒤쪽 상호작용 차단을 검증한다.
4. UI 계약 및 quickstart 시나리오에 따라 디자인, 중복 렌더링, 키보드 접근과 표시 해제를 확인한다.
5. 개발 확인 화면의 최종 동작과 ESLint를 검증한다. Production build는 페이지 통합 또는 배포 전 검증 범위에서 실행한다.
