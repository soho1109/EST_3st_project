## 의존성과 실행 순서

### 단계 의존성

```text
준비(T001~T002)
  ↓
US1 기본 전체 화면 차단(T003~T006)
  ↓
US2 디자인·애니메이션(T007~T009)
  ↓
US3 사용 계약·범위 검증(T010~T012)
  ↓
최종 검증(T013~T016)
```

- 준비 단계 완료 후 사용자 스토리 구현을 시작한다.
- US2는 US1에서 만든 동일 컴포넌트 구조와 스타일에 디자인을 완성하므로 US1 이후 진행한다.
- US3는 완성된 컴포넌트와 개발 확인 화면의 사용 계약을 검증하므로 US2 이후 진행한다.
- 최종 검증은 모든 사용자 스토리 완료 후 개발 환경 동작과 lint를 기준으로 실행한다. 전체 build는 페이지 통합 또는 배포 전 별도 검증한다.

### 사용자 스토리 독립 검증

- **US1(P1)**: 전체 화면 표시·제거와 뒤쪽 상호작용 차단만으로 독립 검증 가능한 MVP다.
- **US2(P2)**: 완성된 Loading을 단독 표시해 디자인과 애니메이션만 독립 비교할 수 있다.
- **US3(P3)**: 파일 목록과 호출 코드를 검사해 단일 소유권 및 범위 준수를 독립 확인할 수 있다.

## 병렬 실행 기회

- T001과 T002는 서로 다른 문서·자산 확인이므로 병렬 수행할 수 있다.
- 사용자 스토리 구현은 `Loading.jsx`, `Loading.module.scss`, 개발 확인 페이지를 단계적으로 공유하므로 안전한 작은 커밋을 위해 순차 수행한다.
- 자동 테스트 파일이나 별도 페이지 파일을 추가하지 않으므로 사용자 스토리 내부에 별도의 안전한 병렬 구현 작업은 없다.

## 참고

- 실제 로그인, 회원가입, 전체·내 요약·북마크 페이지 연결은 후속 기능 작업에서 수행한다.
