# 조사 결과: 회원가입 완료 페이지

## 1. 정적 페이지 구성

**결정**: 회원가입 완료 페이지는 상태와 브라우저 API가 없는 Server Component로 작성한다.

**근거**: 화면은 확정된 안내 콘텐츠와 정적 경로 이동만 제공한다. Client Component로 만들 이유가 없으며 인증·완료 상태 판정도 현재 범위에서 제외됐다.

**검토한 대안**: `useEffect`로 완료 상태를 확인하거나 자동 이동하는 Client Component. 명세에서 인증 판정, 타이머와 자동 이동을 금지하므로 제외한다.

## 2. 로그인 화면 이동

**결정**: `next/link`의 `Link`에 `href="/login"`을 지정한다.

**근거**: `/login`은 사전에 확정된 내부 경로이며 사용자 선택으로 현재 탭에서 이동한다. 프로젝트의 Next.js 규칙과 일치한다.

**검토한 대안**: 일반 `a` 요소와 `useRouter`. 내부 정적 이동에는 `Link`가 우선이며 프로그램 이동이 필요하지 않아 제외한다.

## 3. 마스코트 이미지

**결정**: 기존 `/images/fbee.webp`를 `next/image`로 표시하고 종횡비 기준값을 제공한 뒤 SCSS에서 유연한 너비와 자동 높이를 적용한다.

**근거**: 기존 프로젝트가 같은 자산을 `next/image`로 사용하고 있다. 이미지 공간을 미리 확보하면서 화면별 표시 크기를 바꾸고 원본 비율도 유지할 수 있다.

**검토한 대안**: CSS background-image 또는 일반 `img`. 콘텐츠 의미를 가진 마스코트에 대체 텍스트를 제공하기 어렵거나 기존 이미지 관례와 달라 제외한다.

## 4. 원형 배경 표현

**결정**: 마스코트 래퍼에 CSS `radial-gradient`를 적용한다.

**근거**: 사용자 요구가 별도 이미지 없이 중심에서 바깥으로 은은하게 사라지는 원형 배경을 명시한다. 화면별 크기 조정도 CSS가 단순하다.

**검토한 대안**: Figma의 배경 SVG를 내보내거나 새 PNG를 추가하는 방식. 새 자산을 만들지 않는 조건과 충돌하므로 제외한다.

## 5. 반응형 배치

**결정**: 데스크톱 기본 스타일과 `max-width: 1024px`, `max-width: 480px` 미디어 쿼리를 사용하고, 콘텐츠에는 `width: 100%`와 `max-width`를 함께 적용한다.

**근거**: 제공된 Figma 기준 화면을 직접 대응하면서 중간 화면에서도 고정 너비 때문에 넘치지 않도록 할 수 있다.

**검토한 대안**: 화면별 고정 픽셀 너비만 지정하는 방식. 480px과 기준 사이 화면에서 가로 스크롤이 생길 수 있어 제외한다.

## 6. Header 경계

**결정**: 페이지는 Header를 렌더링하거나 수정하지 않고 상위 사이트 레이아웃에 의존한다.

**근거**: 공통 Header 명세가 `/signup/complete`의 최초 접힘 상태를 이미 규정하며 사용자도 Header와 레이아웃을 작업 범위에서 제외했다.

**검토한 대안**: 페이지가 Header에 접힘 prop을 전달하거나 모바일 Header를 별도로 작성하는 방식. 담당 범위를 침범하고 공통 Header 중복을 만들 수 있어 제외한다.

## 결론

모든 기술 선택이 확정됐으며 미해결 항목은 없다. 구현 범위는 정적 페이지 파일과 대응 SCSS Module로 제한한다.
