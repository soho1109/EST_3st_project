# 기능 명세: 회원가입 완료 페이지

**기능 브랜치**: `feature/signup-complete`

**작성일**: 2026-08-11

**상태**: 계획 준비 완료

**입력**: 데스크톱·태블릿·모바일 Figma와 사용자 확정 문구 및 자산을 기준으로 회원가입 완료 안내 화면을 정의한다.

## 디자인 참조

- [데스크톱 1320px](https://www.figma.com/design/EQgddmgx1PAr79a4uyVyRf/%EC%A0%9C%EB%AA%A9-%EC%97%86%EC%9D%8C?node-id=16-571)
- [태블릿 1024px](https://www.figma.com/design/EQgddmgx1PAr79a4uyVyRf/%EC%A0%9C%EB%AA%A9-%EC%97%86%EC%9D%8C?node-id=16-3606)
- [모바일 480px](https://www.figma.com/design/EQgddmgx1PAr79a4uyVyRf/%EC%A0%9C%EB%AA%A9-%EC%97%86%EC%9D%8C?node-id=16-5126)
- 화면 배경은 `#FBFAF9`, 제목과 안내는 `#222222`, 버튼은 노란색 `#FCCD2A`, 버튼 글자는 남색 `#1A1953`을 기준으로 한다.
- 제목 크기는 데스크톱 `48px`, 태블릿 `36px`, 모바일 `24px`을 기준으로 한다.
- 안내 문구는 데스크톱·태블릿 `20px`, 모바일 `16px`을 기준으로 한다.
- 로그인 이동 영역은 세 화면 모두 높이 `56px`의 둥근 형태를 기준으로 하며 화면 크기에 맞춰 너비가 줄어든다.

## 의존 명세와 작업 범위

- [공통 Header 명세](../001-common-header/Header.md)
- 페이지 경로는 `/signup/complete`다.
- 페이지와 전용 스타일은 각각 `src/app/(site)/signup/complete/page.js`, `src/app/(site)/signup/complete/page.module.scss`에 대응한다.
- Header는 `src/app/(site)/layout.js`에서 한 번 제공되며 페이지가 직접 렌더링하지 않는다.
- `/signup/complete` 최초 진입 시 Header는 공통 Header 명세에 따라 접힌 상태로 시작한다.
- Header와 사이트 공통 레이아웃은 이 페이지 작업에서 수정하지 않는다.
- 공통 Header 명세는 모바일 Header 동작을 범위에서 제외하고 있으므로, 모바일 Figma의 Header 외형은 이 페이지가 직접 구현하지 않고 Header 담당 범위에 맡긴다. 이번 페이지는 모바일 Header 아래의 완료 콘텐츠만 반영한다.
- 중앙 이미지는 기존 `public/images/fbee.webp`를 사용하며 원본 비율을 유지한다.
- 이미지 뒤의 은은한 원형 배경은 별도 이미지 자산을 만들지 않고 중심에서 바깥쪽으로 흐려지는 `radial-gradient` 형태로 표현한다.
- 실제 인증 연동 단계에서는 현재 탭의 회원가입 성공 시각과 로그인 세션을 확인한다. 완료 시각은 개인정보 없이 `sessionStorage`에 저장하고 5분 동안만 완료 화면 접근 근거로 사용한다.

## 사용자 시나리오 및 테스트 _(필수)_

### 사용자 스토리 1 - 가입 완료 확인과 로그인 이동 (우선순위: P1)

회원가입 절차를 마친 사용자는 가입이 완료되었음을 확인하고 로그인 화면으로 이동해 서비스를 계속 이용한다.

**우선순위 이유**: 회원가입 흐름의 결과와 다음 행동을 명확하게 안내하는 것이 이 페이지의 핵심 가치다.

**독립 검증**: `/signup/complete`에 진입해 환영 제목, 마스코트, 완료 안내와 로그인 이동 영역을 확인한 뒤 한 번의 선택으로 `/login`에 도달하는지 검증한다.

**인수 시나리오**:

1. **상황** 사용자가 회원가입 완료 화면에 진입했을 때, **동작** 화면을 확인하면, **결과** `프다에 오신 걸 환영해요!` 제목, 프비 이미지, 원형 그라디언트, 두 줄 완료 안내와 `로그인 하러 가기`가 표시된다.
2. **상황** 완료 안내를 확인한 사용자가, **동작** `로그인 하러 가기`를 선택하면, **결과** 로그인 화면(`/login`)으로 이동한다.
3. **상황** 비로그인 사용자가 유효한 회원가입 완료 표식 없이 직접 접근하면, **동작** 접근 상태가 확인된 뒤, **결과** `접근 권한이 없습니다.` 모달이 표시되고 3초 후 회원가입 화면(`/signup`)으로 이동한다.
4. **상황** 페이지가 표시되어 있을 때, **동작** 사용자가 마스코트 영역을 확인하면, **결과** 이미지는 잘리거나 왜곡되지 않고 배경보다 앞에서 천천히 위아래로 움직인다.
5. **상황** 사용자가 운영체제나 브라우저에서 모션 감소를 설정했을 때, **동작** 완료 화면에 진입하면, **결과** 프비 이미지는 움직이지 않고 정지 상태로 표시된다.

---

### 사용자 스토리 2 - 기기별 완료 화면 확인 (우선순위: P2)

사용자는 데스크톱, 태블릿과 모바일 중 어떤 화면을 사용하더라도 같은 완료 정보와 다음 행동을 확인할 수 있다.

**우선순위 이유**: 화면 크기가 달라도 완료 흐름의 정보와 이동 기능이 누락되면 안 된다.

**독립 검증**: 1320px, 1024px와 480px 화면에서 제목, 마스코트, 안내와 로그인 이동 영역의 표시·순서·넘침 여부를 비교한다.

**인수 시나리오**:

1. **상황** 화면 너비가 1320px일 때, **동작** 완료 화면을 확인하면, **결과** 콘텐츠가 넓은 화면의 중앙 영역에 배치되고 데스크톱 크기의 제목·이미지·버튼이 표시된다.
2. **상황** 화면 너비가 1024px일 때, **동작** 완료 화면을 확인하면, **결과** 콘텐츠가 중앙에 유지되면서 태블릿 기준 크기와 간격으로 축소된다.
3. **상황** 화면 너비가 480px일 때, **동작** 완료 화면을 확인하면, **결과** 좌우 여백 안에 모바일 크기의 제목·이미지·안내·로그인 이동 영역이 세로로 표시되고 가로 스크롤이 생기지 않는다.

### 예외 상황

- `fbee.webp`의 원본 비율과 화면 비율이 달라도 이미지를 늘이거나 자르지 않는다.
- 기준 화면 사이의 너비에서도 콘텐츠가 화면 밖으로 넘치거나 서로 겹치지 않아야 한다.
- 안내 문구는 두 줄 구조를 유지하되 좁은 화면에서도 글자가 잘리지 않아야 한다.
- 로그인 사용자가 직접 접근하면 `alreadyLoggedIn` 모달을 표시하고 공통 모달 계약에 따라 3초 후 메인으로 이동한다.
- 비로그인 사용자의 회원가입 완료 표식이 없거나 기록 시점부터 5분이 지났으면 `접근 권한이 없습니다.` 모달을 표시하고 3초 후 `/signup`으로 이동한다.
- 프비 이미지만 `0`에서 `-18px` 사이를 약 2.8초 동안 천천히 왕복하며, 움직임은 주변 요소의 배치에 영향을 주지 않아야 한다.
- 원형 그라디언트, 제목, 안내 문구와 로그인 이동 영역은 프비 애니메이션과 함께 움직이지 않아야 한다.
- 모션 감소 환경에서는 애니메이션을 중지하고 프비 이미지를 기본 위치에 고정한다.
- 로그인 이동 외에는 자동 이동, 타이머, 새로고침과 자동 로그인을 수행하지 않는다.

## 요구사항 _(필수)_

### 기능 요구사항

- **FR-001**: 시스템은 `/signup/complete`에서 회원가입 완료 안내 화면을 제공해야 한다.
- **FR-002**: 화면은 `프다에 오신 걸 환영해요!` 제목을 표시해야 한다.
- **FR-003**: 화면은 `회원가입이 완료되었어요.`와 `지금부터 나만의 학습을 시작해 보세요.`를 두 줄로 표시해야 한다.
- **FR-004**: 화면은 `fbee.webp` 마스코트를 제목과 안내 사이에 표시해야 한다.
- **FR-005**: 마스코트는 화면 크기에 맞춰 조절되더라도 원본 비율을 유지하고 잘리거나 왜곡되지 않아야 한다.
- **FR-006**: 마스코트 뒤에는 중심에서 바깥쪽으로 은은하게 사라지는 원형 그라디언트를 표시해야 한다.
- **FR-007**: 원형 그라디언트는 별도의 새 이미지 자산에 의존하지 않아야 한다.
- **FR-008**: 화면은 `로그인 하러 가기`라는 노란색 둥근 이동 영역을 제공해야 한다.
- **FR-009**: 사용자가 로그인 이동 영역을 선택하면 로그인 화면(`/login`)으로 이동해야 한다.
- **FR-010**: 로그인 이동은 현재 탭에서 이루어져야 한다.
- **FR-011**: 제목, 마스코트, 안내 문구와 로그인 이동 영역은 세 화면 모두 같은 순서로 표시되어야 한다.
- **FR-012**: 1320px, 1024px와 480px 화면은 각 Figma 기준의 크기·간격 차이를 반영해야 한다.
- **FR-013**: 모든 지원 화면에서 콘텐츠는 중앙 영역에 배치되고 가로 넘침·잘림·요소 겹침이 없어야 한다.
- **FR-014**: 페이지는 Header를 직접 중복 표시하지 않고 사이트 공통 영역에서 제공받아야 한다.
- **FR-015**: `/signup/complete` 최초 진입 시 Header는 공통 Header 정책에 따라 접힌 상태로 시작해야 한다.
- **FR-016**: 이 페이지는 Header와 사이트 공통 영역의 구조나 동작을 변경해서는 안 된다.
- **FR-017**: 이 페이지는 프비 이미지에 `0`에서 `-18px` 사이를 약 2.8초 동안 왕복하는 느린 상하 애니메이션을 제공해야 한다.
- **FR-018**: 이 페이지는 현재 탭의 `sessionStorage`에 기록된 회원가입 완료 시각이 5분 이내인지 확인해야 하며 이메일, 비밀번호, 사용자 ID를 저장해서는 안 된다.
- **FR-019**: 로그인 사용자가 접근하면 CommonModal의 `alreadyLoggedIn` 모드를 표시해야 한다. Loading, Suspense 대체 화면 또는 경로 단위 자동 로딩은 연결하지 않는다.
- **FR-025**: 비로그인 사용자가 유효한 회원가입 완료 표식 없이 접근하면 CommonModal의 `error` 모드와 상태 `403`으로 `접근 권한이 없습니다.`를 표시하고, 3초 후 또는 닫기 선택 시 `/signup`으로 이동해야 한다.
- **FR-020**: 이 기능을 위해 새로운 패키지, 상태 관리 도구 또는 별도 공통 컴포넌트를 추가해서는 안 된다.
- **FR-021**: 프비 애니메이션은 `transform`을 사용해 주변 레이아웃에 영향을 주지 않아야 한다.
- **FR-022**: 프비 애니메이션은 무한 반복하되 원형 그라디언트, 제목, 안내 문구와 로그인 이동 영역을 움직여서는 안 된다.
- **FR-023**: `prefers-reduced-motion: reduce` 환경에서는 프비 애니메이션을 중지하고 기본 위치로 표시해야 한다.
- **FR-024**: 이 페이지는 자동 로그인, 자동 이동, 타이머와 새로고침을 제공해서는 안 된다.

## 성공 기준 _(필수)_

### 측정 가능한 결과

- **SC-001**: 사용자는 완료 화면 진입 후 5초 이내에 회원가입 완료 여부와 다음 행동을 식별할 수 있다.
- **SC-002**: 사용자는 `로그인 하러 가기`를 한 번 선택해 `/login`에 도달할 수 있다.
- **SC-003**: 1320px, 1024px와 480px 검증 화면 모두에서 제목, 마스코트, 원형 배경, 두 줄 안내와 로그인 이동 영역의 누락 사례가 0건이어야 한다.
- **SC-004**: 세 기준 화면과 그 사이 너비에서 콘텐츠 잘림, 이미지 왜곡, 요소 겹침과 의도하지 않은 가로 스크롤이 발생하는 사례가 0건이어야 한다.
- **SC-005**: 페이지 내부에 Header가 중복 표시되거나 인증·모달·로딩·자동 이동이 임의로 실행되는 사례가 0건이어야 한다.
- **SC-006**: 로그인 이동 외의 조작 없이도 모든 완료 정보가 한 화면 흐름 안에서 이해 가능하게 표시되어야 한다.
- **SC-007**: 일반 모션 환경에서 프비 이미지만 지정 범위와 주기로 반복 이동하고 주변 콘텐츠의 위치 변화는 0건이어야 한다.
- **SC-008**: 모션 감소 환경에서 프비 이미지의 반복 이동이 발생하는 사례는 0건이어야 한다.

## 가정

- 사용자는 회원가입 처리 후 이 경로로 이동하며, 현재 탭에 기록된 완료 시각은 민감한 권한 판정이 아닌 완료 안내 흐름 제어에만 사용한다.
- `public/images/fbee.webp`는 현재 이름과 위치를 유지한다.
- 모바일 Header의 구체적인 외형과 동작은 공통 Header 후속 작업에서 제공하며 완료 페이지가 대신 구현하지 않는다.
- 페이지에는 상태, 이벤트 처리 또는 브라우저 전용 API가 필요하지 않으며 로그인 이동만 제공한다.
