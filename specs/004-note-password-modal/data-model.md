# 데이터 모델: 요약 노트 비밀번호 모달

이 기능은 데이터베이스 엔티티를 생성하지 않는다. 아래 모델은 컴포넌트와 호출 측 사이의 일시적인 UI 상태 및 메시지 계약을 나타낸다.

## 비밀번호 입력 상태

| 필드 | 형태 | 소유자 | 규칙 |
|---|---|---|---|
| `password` | 문자열 | `NotePwModal` | 화면에는 마스킹하며 유효한 제출 직후 또는 닫기 시 빈 문자열로 초기화한다. |

### 유효성 규칙

- 빈 문자열과 공백만 있는 문자열은 제출할 수 없다.
- 원문 비밀번호는 화면에 표시하거나 영구 저장하지 않는다.
- 제출 시 호출 측에는 현재 입력값 한 번만 전달한다.

## 모달 표시 상태

| 필드 | 형태 | 소유자 | 규칙 |
|---|---|---|---|
| `isOpen` | Boolean | 호출 측 | 참일 때만 모달과 배경막을 표시한다. |
| `isSubmitting` | Boolean | 호출 측 | 참일 때 입력과 제출을 막아 중복 요청을 방지한다. |
| `errorMessage` | 문자열 | 호출 측 | 비밀번호 불일치일 때 인라인으로 표시한다. 입력값 초기화는 유효한 제출 직후 모달 내부에서 수행한다. |

## 호출 문맥

| 필드 | 의미 | 소유자 |
|---|---|---|
| `summaryId` | 인증 대상 요약 노트 식별자 | 호출 측 |
| `destination` | 인증 성공 후 이동할 보호 경로 | 호출 측 |
| `origin` | 닫기 또는 시스템 오류 후 유지할 페이지 | 호출 측 |

`summaryId`, `destination`, `origin`은 `NotePwModal` props로 직접 전달하지 않는다. 검증과 이동을 수행하는 호출 측 콜백이 해당 문맥을 보존한다.

## 상태 전이

```text
닫힘
  → 잠긴 콘텐츠 선택
열림·입력 가능
  → 빈 값 제출: 상태 유지
  → 닫기: 입력 초기화 → 닫힘
  → 유효한 값 제출: 입력 초기화 → 검증 중
검증 중
  → 추가 제출: 무시
  → 비밀번호 일치: 닫힘 → 호출 측 이동
  → 비밀번호 불일치: 열림·오류 표시·재입력 가능
  → 서버/네트워크 오류: 닫힘 → 호출 측 공통 오류 모달
```

## 외부 인증 상태

동일 브라우저 세션에서 동일 요약 노트의 인증 결과를 유지해야 하지만 저장 형식과 위치는 백엔드 및 인증 계약 확정 전까지 정의하지 않는다. `NotePwModal`은 이 상태를 직접 읽거나 기록하지 않는다.
