# 빠른 시작 및 검증 안내: 학습노트 전체 목록

## 목적

내 학습노트와 모든 노트 목록이 같은 화면 계약을 지키면서 범위별 데이터만 다르게 조회하는지 확인한다. 데이터 필드와 상태 전이는 [데이터 모델](./data-model.md), 조회·오류·라우트 동작은 [인터페이스 계약](./contracts/all-notes-contract.md)을 따른다.

## 사전 조건

- 프로젝트 의존성이 설치되어 있다.
- 기존 Supabase 환경을 사용하는 경우 `.env.local`에 팀이 제공한 URL과 Publishable Key가 설정되어 있다. Secret Key와 `service_role` Key는 사용하지 않는다.
- 기존 `002-summary-detail` 데이터 조회 계약과 Supabase 브라우저 클라이언트가 연결되어 있다.
- 검증 데이터에 다음 항목이 준비되어 있다.
  - 현재 사용자 본인의 학습노트 25개 이상
  - 공개 요약본 1개에 연결된 학습노트 25개 이상
  - 잠긴 요약본 1개와 전체 목록에서 제외되는 상태
  - 같은 `createdAt`을 공유하지만 서로 다른 `noteId`를 가진 항목
  - 항목이 0개인 목록 범위
  - 존재하지 않는 `summaryId`
  - 이미지와 목적지 URL이 모두 있는 배너, 각각 하나씩 누락된 배너 데이터

검증용 데이터는 승인된 기존 서비스나 테스트 어댑터로 준비하며, 이 기능의 quickstart를 위해 마이그레이션·seed 파일을 추가하지 않는다.

## 실행

```bash
npm install
npm run dev
```

### 실제 Supabase 검증 순서

목록은 실제 Supabase의 `summaries`, `learning_notes`, `profiles` 데이터를 조회한다.

1. 개발 서버를 실행하고 `/allnote`를 연다.
2. 첫 응답의 총 개수와 최대 12개 행을 확인한 뒤, 목록 끝까지 이동해 cursor 단위 추가 조회와 중복 제거를 확인한다.
3. `/allnote?summaryId={summaryId}`를 열어 선택한 요약본의 학습노트만 표시되는지 확인한다.
4. 잠긴 요약본의 노트가 `/allnote` 전체 목록에 포함되지 않는지 확인한다.

| 검증 목적 | 경로 또는 데이터 조건 | 예상 데이터·상태 |
|---|---|---|
| 모든 노트 | `/allnote` | 공개 요약본 소속, 모든 작성자, 비로그인 목록 허용 |
| 선택 요약본 | `/allnote?summaryId={summaryId}` | 해당 요약본 소속 노트만 표시 |
| 잠금 제외 확인 | 잠긴 요약본이 포함된 실제 환경 | 잠긴 요약본 소속 노트 0건 |
| 빈 목록 | 연결된 학습노트가 없는 실제 요약본 | 0개, `EmptyState`만 표시 |
| 일반 오류 | 실제 조회 실패 환경 | `CommonModal` 500 오류 후 `/` 이동 |

같은 작성 시각을 가진 실제 학습노트와 12개 단위 페이지를 사용해 cursor 경계를 검증한다. `/mypage/summaries`는
현재 담당자 구현 범위로 제외되어 이 브랜치에서는 페이지 파일을 유지·수정하지 않는다. 아래
요약본 경로 검증을 먼저 진행하고, 마이페이지 담당자가 경로를 다시 연결한 뒤 시나리오 1·5·7을
추가로 실행한다.

브라우저에서 다음 경로를 직접 연다.

```text
/allnote
/mypage/summaries
```

## 시나리오 1: 내 학습노트 목록

1. 로그인한 상태로 `/mypage/summaries`를 연다.
2. 상단에 `총 {count}개의 학습노트`가 표시되는지 확인한다.
3. 첫 화면에 최신 작성일 순으로 최대 12개가 표시되는지 확인한다.
4. 각 행에 퀴즈 상태 이미지, 작성자 닉네임, 주제, `YYYY.MM.DD` 작성일이 표시되는지 확인한다.
5. 행을 선택해 해당 `summaryId`와 `noteId`의 `/summary/{summaryId}/notes/{noteId}`로 이동하는지 확인한다.

**예상 결과**: 퍼센트 값이나 별도 CTA 없이 목록과 상세 이동이 정확히 표시된다.

## 시나리오 2: 12개 단위 추가 조회와 중복 방지

1. 25개 이상의 항목이 있는 목록에서 첫 12개가 표시될 때까지 기다린다.
2. 목록 끝으로 스크롤해 다음 묶음을 요청한다.
3. 같은 위치에서 빠르게 여러 번 스크롤하거나 sentinel이 계속 보이는 상태를 만든다.
4. 두 번째 묶음이 한 번만 요청되고 첫 묶음과 중복되지 않는지 확인한다.
5. 마지막 묶음이 1개이거나 12개 미만일 때 추가 감시가 종료되는지 확인한다.
6. 같은 작성 시각의 항목이 누락되지 않고 `noteId` 보조 정렬 순서를 유지하는지 확인한다.

**예상 결과**: 화면에는 중복 행이 없고, 더 가져올 데이터가 없으면 추가 요청이 발생하지 않는다.

## 시나리오 3: 모든 작성자의 공개 노트 목록

1. 로그아웃 또는 비로그인 상태로 `/allnote`를 연다.
2. 로그인 요구 모달 없이 공개 요약본에 속한 모든 작성자의 행이 표시되는지 확인한다.
3. 잠긴 요약본에 속한 행은 표시되지 않는지 확인한다.
4. 행 선택 시 행의 `summaryId`와 `noteId`를 사용하는 상세 경로로 이동하는지 확인한다.

**예상 결과**: `/allnote`는 로그인 여부와 무관하게 공개 요약본의 학습노트를 조회한다.

## 시나리오 4: 잠긴 요약본 노트 비노출

1. `/allnote`를 연다.
2. `summary-002`처럼 잠긴 요약본에 소속된 노트가 목록에 없는지 확인한다.
3. `/allnote`에서 잠금 비밀번호 모달이 표시되지 않는지 확인한다.

**예상 결과**: 전체 목록에서는 잠금 요약본 노트가 0건이며, 잠금 인증은 요약본 상세 기능에서만 수행된다.

## 시나리오 5: 비로그인 내 목록 접근

1. 로그아웃 상태로 `/mypage/summaries`를 연다.
2. 목록 내용이 모달 뒤에 노출되지 않는지 확인한다.
3. 모달을 즉시 닫거나 그대로 둔 뒤 접근 시점부터 3초가 지나도록 기다린다.

**예상 결과**: 접근 제한 모달이 표시되고 `/login`으로 이동한다.

## 시나리오 6: 빈 목록

1. 항목이 0개인 내 목록 또는 요약본 목록을 연다.
2. `학습 노트 리스트가 아직 생성되지 않았습니다.`가 한 번 표시되는지 확인한다.
3. 목록 행, 추가 로딩 sentinel, 생성·작성 CTA가 함께 표시되지 않는지 확인한다.

**예상 결과**: 정상 빈 결과에서만 기존 `EmptyState`가 표시되고 오류·로딩 상태와 섞이지 않는다.

## 시나리오 7: 오류와 없는 요약본

1. 실제 Supabase 조회가 실패하는 테스트 환경을 설정한다.
2. `/mypage/summaries`와 `/allnote`에서 각각 오류 모달을 확인한다.
3. 모달을 닫은 뒤 각각 `/mypage`, `/`로 이동하는지 확인한다.
4. 행의 상세 링크가 없는 `summaryId`를 가리키는 경우 기존 상세 계약의 404 처리를 확인한다.

**예상 결과**: 전체 목록 오류는 공통 오류 모달 후 `/`로 이동하고, 추가 로딩 실패 시 이미 표시한 행은 사라지지 않는다.

## 시나리오 8: 배너와 데스크톱 레이아웃

1. 이미지와 목적지 URL이 모두 유효한 배너를 선택해 지정된 내부 또는 외부 목적지로 이동하는지 확인한다.
2. 이미지 또는 목적지 URL이 없는 배너가 이동 가능한 링크가 아닌지 확인한다.
3. 1440px 데스크톱 프레임에서 Header가 펼친 상태로 시작하는지 확인한다.
4. 긴 닉네임과 주제를 넣어도 행 열 경계와 전체 레이아웃이 깨지지 않는지 확인한다.
5. 모바일·태블릿 전용 동작이나 별도 레이아웃이 추가되지 않았는지 확인한다.

## 정적 검증

```bash
npm run lint
npm run build
git diff --check
```

**통과 기준**:

- lint와 production build가 성공한다.
- 두 경로에서 총 개수, 최신순, 12개 단위 추가, 중복 0건이 확인된다.
- 잠긴 요약본 노트와 비로그인 내 목록의 보호 콘텐츠 노출이 0건이다.
- 빈 목록·일반 오류·상세 404의 문구와 후속 이동이 계약과 일치한다.
- 기존 `NoteItem`, `Banner`, `EmptyState`, `CommonModal`, `NotePwModal`, Supabase 공통 클라이언트의 범위를 벗어난 변경이 없다.
