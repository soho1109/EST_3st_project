# 기능 명세: 요약 및 학습노트 상세

**기능 브랜치**: `feature/summary-detail`

**작성일**: 2026-08-05

**최종 수정일**: 2026-08-18

**상태**: 영속 데이터 기반 요약본 삭제·학습노트·북마크 명세 준비 완료

**입력**: 사용자 설명: "요약 상세 기능을 영속 데이터와 연결해 학습노트 생성·조회·수정·삭제와 북마크 저장을 지원한다."

## 현재 영속 데이터 증분 범위

- 경로 식별자와 일치하는 요약본 및 소속 학습노트를 영속 데이터에서 조회해 상세 화면에 표시한다.
- 로그인 사용자는 현재 요약본에 학습노트를 생성하고, 자신이 작성한 학습노트를 수정하거나 삭제할 수 있다.
- 학습노트 생성·수정 결과는 다시 조회했을 때 유지되며 삭제한 학습노트는 목록과 직접 경로에서 더 이상 제공되지 않는다.
- 로그인 사용자는 요약본의 북마크를 저장하거나 해제할 수 있고, 저장 상태는 다시 방문하거나 새로고침한 뒤에도 유지된다.
- 생성·수정·삭제 및 북마크 변경은 로그인 사용자와 콘텐츠 소유권을 기준으로 허용한다.
- 요약본 생성·수정, 비밀번호 잠금 인증, 퀴즈 조회·제출·저장은 이번 증분에 포함하지 않는다. 요약본 삭제는 사용자 승인으로 이번 증분에 포함한다.
- 기존 읽기 전용 검증 데이터 연결 요구사항은 이전 증분의 검증 기준으로 유지하되, 현재 증분의 성공 여부는 영속 데이터 동작을 기준으로 판단한다.

## 사용자 시나리오 및 테스트 _(필수)_

### 사용자 스토리 1 - 요약본과 학습노트 목록 확인 (우선순위: P1)

방문자는 생성 주제와 AI 요약본을 읽고, 연결된 학습노트가 있으면 최신 작성순으로 목록을 확인한다. 목록에는 퀴즈 학습 상태, 작성자, 주제, 작성일이 표시되며 항목을 선택하면 상세 페이지로 이동한다.

**우선순위 이유**: 생성된 요약 정보와 관련 학습 자료를 확인하는 것이 이 기능의 핵심 가치다.

**독립 검증**: 학습노트가 있는 요약본과 없는 요약본에 각각 접근하여 목록 상태, 표시 정보, 상세 이동을 검증할 수 있다.

**인수 시나리오**:

1. **상황** 접근 가능한 요약본에 학습노트가 존재하고, **동작** 사용자가 요약본 상세 페이지를 열면, **결과** 생성 주제, AI 요약본 및 최신 작성순 학습노트 목록이 표시된다.
2. **상황** 학습노트 목록이 표시되고, **동작** 사용자가 한 항목을 선택하면, **결과** 선택한 학습노트의 상세 페이지로 이동한다.
3. **상황** 요약본에 학습노트가 없고, **동작** 사용자가 요약본 상세 페이지를 열면, **결과** 빈 목록 안내 상태가 표시된다.
4. **상황** 목록이 표시되고, **동작** 사용자가 `더보기`를 선택하면, **결과** 전체 노트 페이지로 이동한다.

---

### 사용자 스토리 2 - 학습노트 작성 및 수정 (우선순위: P1)

로그인한 사용자는 요약본을 바탕으로 제목, 오늘 배운 내용 요약, 오늘의 회고 및 참고자료를 기록하고, 자신이 작성한 학습노트를 나중에 수정할 수 있다.

**우선순위 이유**: 사용자가 AI 요약본을 개인 학습 기록으로 확장하고 유지하는 핵심 작업이다.

**독립 검증**: 로그인 사용자가 제목만 입력하거나 선택 본문을 함께 입력해 생성한 후 상세 화면에서 확인하고 수정하는 전체 흐름을 검증할 수 있다.

**인수 시나리오**:

1. **상황** 로그인한 사용자가 작성 페이지에 있고, **동작** 유효한 제목과 선택 본문을 제출하면, **결과** 요청 처리 중 전체 화면 로딩이 표시되고 성공 후 생성된 학습노트 상세로 이동한다.
2. **상황** 작성자가 수정 페이지에 접근하고, **동작** 기존 값을 변경하여 제출하면, **결과** 요청 처리 중 전체 화면 로딩이 표시되고 성공 후 수정된 학습노트 상세로 이동한다.
3. **상황** 제목이 비어 있거나 공백만 있고, **동작** 사용자가 제출하거나 제목 입력란을 벗어나면, **결과** `제목을 입력해 주세요.`가 표시되고 요청은 전송되지 않는다.
4. **상황** 입력값이 최대 길이를 초과하고, **동작** 사용자가 입력란을 벗어나거나 제출하면, **결과** 해당 길이 오류가 표시되고 요청은 전송되지 않는다.

---

### 사용자 스토리 3 - 접근 권한과 잠긴 요약본 처리 (우선순위: P1)

비밀번호로 보호된 요약본과 모든 하위 학습노트는 인증된 사용자만 열 수 있으며, 작성·수정·삭제 동작은 로그인 및 소유권 조건에 따라 제한된다.

**우선순위 이유**: 보호된 콘텐츠와 작성자 전용 작업이 권한 없이 노출되거나 변경되는 것을 막아야 한다.

**독립 검증**: 잠긴 요약본의 네 경로, 비로그인 작성 접근, 비작성자 수정 접근을 각각 직접 열어 예상되는 인증 및 이동 결과를 확인할 수 있다.

**인수 시나리오**:

1. **상황** 요약본이 비밀번호로 잠겨 있고 현재 브라우저 세션에서 인증되지 않았으며, **동작** 사용자가 요약본 또는 하위 학습노트 경로에 접근하면, **결과** 콘텐츠보다 먼저 비밀번호 입력 모달이 표시된다.
2. **상황** 비밀번호가 일치하지 않고, **동작** 사용자가 인증을 시도하면, **결과** `비밀번호가 일치하지 않습니다.`가 표시되고 재입력할 수 있다.
3. **상황** 비밀번호 인증이 성공하고, **동작** 사용자가 같은 브라우저 세션에서 동일 요약본의 하위 경로로 이동하면, **결과** 추가 인증 없이 콘텐츠가 표시된다.
4. **상황** 비로그인 사용자가 학습노트 작성 URL에 직접 접근하면, **결과** 로그인 페이지로 이동한다.
5. **상황** 비작성자가 학습노트 수정 URL에 직접 접근하면, **결과** 현재 요약 상세 페이지로 이동한다.

---

### 사용자 스토리 4 - 요약본과 학습노트 삭제 (우선순위: P2)

작성자는 확인 절차를 거쳐 자신이 작성한 요약본 또는 학습노트를 삭제할 수 있다.

**우선순위 이유**: 사용자가 자신이 만든 콘텐츠의 수명 주기를 관리할 수 있어야 한다.

**독립 검증**: 작성자와 비작성자 상태에서 삭제 버튼 노출 여부를 확인하고, 확인 및 취소 결과를 검증할 수 있다.
**인수 시나리오**:

1. **상황** 요약본 작성자가 학습노트가 없는 요약본의 삭제를 선택하고, **동작** 확인 모달에서 삭제를 승인하면, **결과** 요약본이 삭제되고 전체 노트 페이지로 이동한다. 학습노트가 있는 요약본은 삭제할 수 없다.
2. **상황** 학습노트 작성자가 삭제를 선택하고, **동작** 확인 모달에서 삭제를 승인하면, **결과** 해당 학습노트가 삭제되고 소속 요약 상세 페이지로 이동한다.
3. **상황** 사용자가 삭제 확인 모달에서 취소하면, **결과** 데이터 변경 없이 현재 페이지가 유지된다.
4. **상황** 사용자가 해당 콘텐츠의 작성자가 아니면, **결과** 삭제 버튼이 표시되지 않는다.

---

### 사용자 스토리 5 - 북마크와 퀴즈 이용 (우선순위: P3)

로그인 사용자는 요약본의 북마크 상태를 전환하고, 저장된 학습노트 퀴즈를 풀어 채점 결과를 확인할 수 있다. 비로그인 사용자가 퀴즈를 선택하면 로그인 안내를 받는다.

**우선순위 이유**: 핵심 조회·작성 흐름 이후 반복 학습과 콘텐츠 재접근을 지원한다.

**독립 검증**: 로그인 여부에 따른 북마크와 퀴즈 동작, 답안 선택 및 채점 결과 표시를 별도로 검증할 수 있다.

**인수 시나리오**:

1. **상황** 로그인 사용자가 요약본을 보고 있고, **동작** 북마크 아이콘을 선택하면, **결과** 북마크 저장 상태가 반대로 전환되어 표시된다.

2. **상황** 로그인 사용자가 저장된 퀴즈가 있는 학습노트 상세에 있고, **동작** 퀴즈 풀기를 선택하면, **결과** 퀴즈 모달에서 문제와 답안을 확인할 수 있다.
3. **상황** 퀴즈 모달이 열려 있고, **동작** 사용자가 답안을 선택해 제출하면, **결과** 채점 결과가 표시되고 사용자는 모달을 닫을 수 있다.
4. **상황** 비로그인 사용자가 퀴즈 풀기를 선택하면, **결과** 로그인 제안 모달이 표시된다.

---

### 사용자 스토리 6 - 영속 학습노트와 북마크 확인 (우선순위: P1)

로그인 사용자는 자신이 생성하거나 변경한 학습노트와 북마크 상태가 저장되어 이후 조회에서도 같은 결과로 유지되는 것을 확인할 수 있다.

**우선순위 이유**: 작성한 학습 기록과 저장한 요약본이 일시적인 화면 상태로 사라지지 않아야 실제 서비스 가치가 성립한다.

**독립 검증**: 로그인 사용자가 학습노트를 생성·조회·수정·삭제하고 북마크를 저장·해제한 뒤 각 화면을 새로고침하여 확정된 상태가 유지되는지 검증할 수 있다.

**인수 시나리오**:

1. **상황** 로그인 사용자가 유효한 학습노트를 생성했고, **동작** 상세 화면을 새로고침하거나 나중에 다시 열면, **결과** 저장된 제목과 본문이 동일하게 표시된다.
2. **상황** 작성자가 학습노트를 수정했고, **동작** 목록과 상세 화면을 다시 조회하면, **결과** 변경된 값이 표시되고 이전 값은 표시되지 않는다.
3. **상황** 작성자가 학습노트를 삭제했고, **동작** 소속 요약본 목록이나 삭제된 학습노트 경로를 열면, **결과** 목록에 나타나지 않으며 직접 경로는 찾을 수 없음으로 처리된다.
4. **상황** 로그인 사용자가 북마크를 저장하거나 해제했고, **동작** 페이지를 새로고침하거나 다시 방문하면, **결과** 마지막으로 확정된 북마크 상태가 표시된다.
5. **상황** 다른 사용자가 소유한 학습노트의 변경을 시도하고, **동작** 수정 또는 삭제 요청을 보내면, **결과** 데이터는 변경되지 않고 권한이 없음을 알 수 있는 오류 상태가 표시된다.

### 예외 상황

- 존재하지 않는 요약본 또는 학습노트 식별자로 접근하면 찾을 수 없음 페이지가 표시된다.
- 비밀번호 모달을 취소하면 사용자가 직전에 보던 페이지로 돌아간다.
- 생성·수정·삭제·북마크 요청이 실패하면 공통 오류 모달 영역에 오류가 표시되며 현재 입력 또는 페이지 상태는 보존된다.
- 요청 처리 중에는 전체 화면 로딩이 표시되고 제출 동작이 비활성화되어 중복 요청을 막는다.
- 동일한 사용자와 요약본의 북마크 저장 요청이 반복되어도 북마크 관계는 하나만 유지된다.
- 북마크 변경 요청이 실패하면 화면은 실패한 변경을 저장된 상태로 표시하지 않고 마지막으로 확인된 상태를 유지한다.
- 학습노트가 조회된 뒤 다른 곳에서 삭제되거나 변경 권한이 사라진 상태로 수정·삭제를 시도하면, 변경되지 않았음을 알리고 최신 상태를 다시 확인할 수 있게 한다.
- 제목 또는 본문의 앞뒤 공백은 유효성 판단 전에 제거되며, 공백만 있는 제목은 빈 값으로 처리한다.
- 저장된 퀴즈가 없거나 조회에 실패한 경우 퀴즈를 풀 수 없는 상태임을 모달에서 알린다.
- 학습노트의 작성자 데이터가 없으면 화면이 중단되지 않고 알 수 없는 작성자로 표시한다.
- 검증용 학습노트에 수정 양식의 선택 필드가 모두 없으면 제공되는 본문은 오늘 배운 내용에 표시하고 나머지 선택 필드는 빈 값으로 표시한다.
- 비공개로 표시된 검증용 요약본은 이번 증분에서 잠금 보안을 검증하는 근거로 사용하지 않는다.
- 이전 증분의 검증용 원본 데이터는 변경하지 않으며, 현재 증분의 쓰기 결과는 영속 데이터에서만 확정한다.

## 요구사항 _(필수)_

- **브라우저 세션 인증**: 잠긴 요약본 식별자와 인증 완료 여부를 연결해 동일 세션의 하위 경로 접근을 허용하는 상태.

## 성공 기준 _(필수)_

### 최종 기능 성공 기준

- **SC-001**: 사용자는 접근 가능한 요약본에서 생성 주제, AI 요약본 및 학습노트 목록 상태를 3초 이내에 확인할 수 있다.
- **SC-002**: 로그인 사용자는 유효한 입력으로 학습노트 생성 또는 수정 흐름을 2분 이내에 완료하고 결과 상세 페이지에 도달할 수 있다.
- **SC-003**: 권한 검증 시나리오에서 비로그인 작성 접근, 비작성자 수정 접근 및 비작성자 삭제 버튼 노출이 100% 정의된 결과로 차단된다.
- **SC-004**: 잠긴 요약본의 네 경로 모두 인증 전에는 보호 콘텐츠가 노출되지 않으며, 인증 후 동일 브라우저 세션에서는 재인증 없이 접근할 수 있다.
- **SC-005**: 유효하지 않은 제목으로 시도한 생성·수정 요청은 100% 차단되고 사용자는 해당 입력란에서 오류 원인을 확인할 수 있다.
- **SC-006**: 생성·수정 요청 중 연속 클릭을 시도해도 사용자 행동 한 번당 저장 요청은 하나만 처리된다.
- **SC-007**: 작성자가 확인한 삭제 작업은 대상과 정의된 연관 데이터를 제거하고 3초 이내에 해당 삭제 유형에 정의된 경로로 이동한다.
- **SC-008**: 저장된 퀴즈가 있는 학습노트에서 사용자는 문제 확인, 답안 선택, 제출 및 채점 결과 확인을 하나의 모달 흐름에서 완료할 수 있다.

### 현재 read-only 증분 성공 기준

- **SC-009**: 준비된 모든 유효 요약본 경로에서 해당 식별자의 주제와 AI 요약 내용이 100% 일치하게 표시된다.
- **SC-010**: 학습노트 목록 검증에서 다른 요약본의 항목이 섞이거나 최신순 정렬이 어긋나는 사례가 0건이다.
- **SC-011**: 준비된 모든 유효 학습노트에서 상세 내용, 작성자와 수정 화면 기존 값이 검증 데이터와 100% 일치한다.
- **SC-012**: 존재하지 않거나 관계가 불일치하는 요약본·학습노트 경로가 정상 콘텐츠를 표시하는 사례가 0건이다.
- **SC-013**: 검증 전후 원본 데이터 비교에서 변경된 항목이 0건이다.

### 현재 영속 데이터 증분 성공 기준

- **SC-014**: 로그인 사용자는 유효한 학습노트 생성 또는 수정 후 3초 이내에 결과 상세 화면에서 확정된 내용을 확인할 수 있다.
- **SC-015**: 생성·수정된 모든 검증 대상 학습노트는 페이지 새로고침과 재접속 후에도 마지막으로 확정된 내용과 100% 일치한다.
- **SC-016**: 삭제가 확정된 모든 검증 대상 학습노트가 목록 또는 직접 경로에서 다시 제공되는 사례가 0건이다.
- **SC-017**: 비로그인 생성과 비작성자 수정·삭제 검증 시도에서 데이터가 변경되는 사례가 0건이다.
- **SC-018**: 북마크 저장·해제 검증에서 새로고침 및 재방문 후 표시 상태가 마지막 확정 상태와 일치하는 비율은 100%다.
- **SC-019**: 동일 사용자와 요약본에 대한 반복 북마크 저장 후 중복된 활성 북마크 관계가 생기는 사례가 0건이다.
- **SC-020**: 실패하도록 만든 생성·수정·삭제·북마크 요청에서 성공 안내가 표시되거나 마지막 확정 데이터가 의도치 않게 변경되는 사례가 0건이다.

## 의존성

- 현재 로그인 사용자 식별자를 신뢰할 수 있게 제공하는 프로젝트 공통 인증 기능이 학습노트 쓰기와 북마크 저장 전에 준비되어야 한다.
- 요약본과 사용자 데이터가 영속 데이터에 존재하며 학습노트와 북마크가 이를 참조할 수 있어야 한다.
- 공통 오류 모달과 로그인 이동 흐름은 기존 공통 UI 계약을 따른다.

## 가정

- 영속 데이터 증분에서는 고정 검증 사용자가 아니라 프로젝트 공통 인증이 제공하는 현재 로그인 사용자를 사용한다.
- 이전 검증용 데이터는 팀 DB로 이관하지 않으며 학습노트 CRUD 또는 북마크 저장 대상으로 사용하지 않는다.
- 팀 DB 검증에는 임시 공개 요약본 한 건만 사용하고 확인 후 관련 학습노트·북마크와 함께 제거한다.
- 사용자 인증 방식과 세션 구조는 프로젝트 공통 인증 명세에서 정의하며 이번 명세에서 새로 결정하지 않는다.
- 학습노트 작성자는 생성 시점의 로그인 사용자로 확정되며 이후 다른 사용자로 변경되지 않는다.
- 퀴즈 상태는 이번 증분에서 새로 생성하거나 변경하지 않고, 조회 가능한 기존 값이 있으면 표시만 한다.
- 공통 헤더, 공통 오류·삭제·로그인 제안 모달, 비밀번호 모달, 퀴즈 모달 및 빈 목록 표현은 각각의 별도 명세나 공통 UI 계약을 따른다.
- 서버 오류의 정확한 사용자 문구는 이번 기능에서 확정하지 않으며 공통 오류 모달이 제공하는 표현을 따른다.
- 퀴즈 백분율 점수는 학습노트 목록에 표시하지 않으며 목록에는 작성일만 표시한다.
- 본 명세는 제공된 데스크톱 디자인 프레임의 화면 구성과 상태를 대상으로 한다.
- 원본 요구사항과 Figma가 충돌하는 경우 기능 동작과 권한은 원본 요구사항 및 사용자 확정 결정을, 배치와 시각적 외형은 Figma를 따른다.
