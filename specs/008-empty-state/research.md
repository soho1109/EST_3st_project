# 조사 결과: 공통 빈 상태 안내

## 표시 책임의 분리

**결정**: `EmptyState`는 이미지와 전달받은 문구만 렌더링하고, 빈 목록 여부와 로딩·오류 판정은 호출 영역이 소유한다.

**근거**: 전체 요약 목록, 마이페이지와 요약 상세는 서로 다른 데이터 소유자와 상태 흐름을 갖는다. 공통 컴포넌트가 데이터나 페이지 종류를 알게 되면 명세 범위를 넘어 결합도가 커진다.

**대안**: `items`, `isLoading`, `hasError`, `view`를 모두 받는 컴포넌트는 호출 코드를 줄일 수 있지만 표시 컴포넌트가 목록 정책까지 소유하게 되어 제외한다.

## 공개 입력 계약

**결정**: 공개 입력은 필수 문자열 `message` 하나로 제한하고 페이지별 크기·이미지·행동 prop은 제공하지 않는다.

**근거**: 세 문구 외의 시각적 구조는 모든 적용 대상에서 동일해야 하며 빈 상태에는 동작이 없다. 문구만 호출자가 선택하면 정확한 책임 경계와 재사용성을 함께 유지할 수 있다.

**대안**: `variant`로 문구를 내부 매핑하면 오탈자를 줄일 수 있지만 컴포넌트가 페이지 문맥을 알아야 하고 향후 문구 추가 때 공개 API를 확장해야 하므로 제외한다. `children`은 허용 범위가 넓어 명세에 없는 복합 콘텐츠가 들어갈 수 있어 제외한다.

## 렌더링 경계

**결정**: 상태와 이벤트가 없는 기본 렌더링 컴포넌트로 두며 Client Component 선언을 추가하지 않는다.

**근거**: `message`, 정적 이미지와 스타일만 사용하므로 브라우저 상태가 필요 없다. 호출 영역이 Client Component여도 하위의 단순 표시 컴포넌트를 사용할 수 있다.

**대안**: EmptyState 내부에서 표시 여부를 상태로 관리하면 호출 영역의 목록 상태와 이중 소유가 생기므로 제외한다.

## 이미지와 스타일 재사용

**결정**: 요약 상세가 이미 사용하는 `/images/clear.webp`와 해당 이미지 크롭·중앙 정렬 스타일을 공통 SCSS Module로 이동한다.

**근거**: 새 자산 없이 현재 디자인을 보존하면서 모든 적용 대상의 시각적 구조를 동일하게 만들 수 있다. 지역 스타일을 남기면 같은 역할의 규칙이 중복된다.

**대안**: 새 이미지 생성이나 페이지별 스타일 복제는 명세에 없고 공통 표현의 일관성을 해치므로 제외한다.

## Grid와 일반 흐름 배치

**결정**: 공통 루트가 부모 너비를 사용하고 Grid 컨테이너 안에서는 전체 열을 차지하게 한다.

**근거**: `Allsummary`와 마이페이지 북마크는 다열 Grid이고 요약 상세는 일반 문서 흐름이다. 같은 컴포넌트가 한 카드 폭으로 축소되지 않으면서 두 배치에서 동일하게 중앙 정렬되어야 한다.

**대안**: 호출 페이지마다 별도 wrapper 스타일을 추가하면 적용 파일과 중복 규칙이 늘어나므로 제외한다.

## 빈 상태와 다른 상태의 상호 배제

**결정**: 정상 결과가 확정되고 항목 수가 0일 때만 EmptyState를 표시한다. 로딩·오류·항목 존재 상태와 동시에 렌더링하지 않는다.

**근거**: 빈 목록은 성공적으로 확인된 결과이며 로딩과 실패는 의미가 다르다. 명세의 SC-003과 기존 Loading·오류 정책을 보존하려면 상태가 상호 배타적이어야 한다.

**대안**: 초기 배열이 비었다는 이유만으로 즉시 EmptyState를 표시하면 조회 중 빈 화면이 깜박이고 실패를 빈 결과로 오인하게 되어 제외한다.

## 마이페이지 정적 데이터 경계

**결정**: 현재 하나의 정적 placeholder 배열을 공유하는 내 요약 노트와 북마크 컬렉션을 분리하고, 북마크는 실제 데이터 서비스 연결 전의 빈 표시 상태로 둔다. 임시 상태의 변경 범위를 코드 주석에 명시한다.

**근거**: 두 섹션은 서로 독립된 데이터이며 하나의 배열을 공유하면 북마크만 빈 경우를 표현할 수 없다. 이번 기능은 서버 조회 구조를 결정할 권한이 없으므로 페이지 내 최소 정적 경계만 분리한다.

**대안**: 목 JSON을 마이페이지에 새로 연결하면 작성자 결합·정렬·표시 개수까지 페이지 데이터 구현 범위로 확장되므로 제외한다. 기존 공유 배열을 유지하면 요구된 마이페이지 북마크 EmptyState를 검증할 수 없어 제외한다.

## 실제 경로의 대소문자

**결정**: 현재 Git이 추적하는 `Summary`, `Mypage`, `Allsummary.jsx` 경로를 그대로 사용하고 이번 기능에서 소문자 경로나 PascalCase 파일명으로 바꾸지 않는다.

**근거**: 원본 문서와 `AGENTS.md`의 예시 경로는 주로 소문자이지만 현재 제품 코드와 import는 대문자 앱 폴더 및 `Allsummary.jsx`에 연결되어 있다. 대소문자 변경은 여러 경로와 import에 영향을 주며 EmptyState의 단일 기능 범위를 벗어난다.

**대안**: 이번 작업에서 경로까지 일괄 정규화하면 case-sensitive 배포 위험을 별도로 해결할 수 있지만, 관련 없는 파일 변경과 라우팅 영향 검증이 필요하므로 제외한다. 경로 정규화는 별도 기능으로 다룬다.

## 접근성

**결정**: 빈 상태 루트에 상태 의미와 정중한 live 안내를 제공하고 이미지는 빈 대체 설명의 장식 이미지로 처리한다. 접근성 속성의 목적을 코드 주석으로 남긴다.

**근거**: 검색이나 목록 갱신 후 빈 상태가 동적으로 나타날 수 있으므로 보조 기술에도 변화가 전달되어야 한다. 이미지와 문구를 모두 읽으면 의미가 중복된다.

**대안**: 일반 문단만 사용하면 최초 탐색으로는 읽을 수 있지만 동적 결과 변화를 자동으로 알리기 어렵다. 이미지에 설명을 넣으면 안내 문구와 중복될 가능성이 있어 제외한다.

## 검증 전략

**결정**: 새 테스트 라이브러리를 도입하지 않고 적용 페이지 수동 시나리오, ESLint, production build와 변경 형식 검사를 사용한다.

**근거**: 프로젝트에는 별도 테스트 스크립트가 없으며 새 패키지는 금지되어 있다. 이 기능의 핵심은 정확한 문구, 조건부 표시, 시각적 배치와 접근성 구조이므로 브라우저 확인과 기존 정적 검증으로 범위에 맞게 검증할 수 있다.

**대안**: 테스트 프레임워크 도입은 이 단일 표시 기능의 범위를 넘어 제외한다.
