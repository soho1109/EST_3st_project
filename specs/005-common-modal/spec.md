**기능 브랜치**: `feature/common-modal`

**작성일**: 2026-08-07

**상태**: 초안

## 범위

이 기능은 준비 중 안내, 삭제 확인, 선택형 로그인 권유, 보호 페이지 로그인 접근 제한, 이미 로그인된 사용자 안내, 시스템 오류 안내를 하나의 공통 모달에서 `mode`에 따라 구분하여 표시하는 범위까지 포함한다. 실제 삭제 요청, API 및 데이터베이스 연결, 사용자 인증 상태 판단과 입력 검증 오류 표시는 범위에서 제외한다.

공통 모달은 고정된 로그인 및 자동 이동 모드의 경로와 타이머를 직접 처리한다. 삭제 대상과 실제 삭제 작업은 호출 화면이 알고 있으므로 공통 모달은 삭제 승인 또는 취소 선택만 호출 측에 전달한다.

## 공통 모드

| `mode`            | 사용 상황                                 | 기본 문구                                         | 제공 동작                                           |
| ----------------- | ----------------------------------------- | ------------------------------------------------- | --------------------------------------------------- |
| `preparing`       | 아직 제공하지 않는 기능                   | `현재 준비 중입니다.`                             | 닫기                                                |
| `confirmDelete`   | 요약 노트 또는 학습노트 삭제 전           | `정말 삭제하시겠습니까?`                          | 삭제, 취소, 닫기                                    |
| `suggestLogin`    | 공개 페이지에서 인증이 필요한 기능 선택   | `로그인이 필요합니다.`                            | 로그인 이동, 전체 요약 노트 이동, 닫기              |
| `requireLogin`    | 비로그인 사용자가 보호 페이지에 직접 접근 | `로그인이 필요합니다.`                            | 3초 후 로그인 이동, 닫으면 즉시 로그인 이동         |
| `alreadyLoggedIn` | 로그인 사용자가 회원가입 페이지 접근      | `이미 로그인하셨습니다. 메인페이지로 이동합니다.` | 3초 후 메인 이동, 닫으면 즉시 메인 이동             |
| `error`           | 시스템·서버·네트워크 오류                 | 상태에 맞는 오류 문구                             | 3초 후 자동 닫기 또는 즉시 닫기 후 현재 페이지 유지 |

`mode`는 여러 값 중 하나를 선택하므로 Boolean 상태를 뜻하는 `isMode`가 아니라 `mode`라는 이름을 사용한다.

## 사용자 시나리오 및 테스트 _(필수)_

### 사용자 스토리 1 - 공통 안내 모드 이용 (우선순위: P1)

사용자는 준비 중, 로그인 필요, 이미 로그인된 상태와 같은 상황에서 일관된 디자인의 안내와 명확한 다음 동작을 제공받는다.

**우선순위 이유**: 여러 페이지에서 반복되는 안내를 같은 방식으로 이해하고 이용할 수 있어야 한다.

**독립 검증**: 각 안내 모드를 차례로 표시해 프비 이미지, 문구, 버튼 구성, 닫기 및 자동 이동 결과가 모드 계약과 일치하는지 확인한다.

**인수 시나리오**:

1. **상황** 사용자가 아직 제공되지 않는 기능을 선택했을 때, **동작** `preparing` 모달을 닫으면, **결과** 현재 페이지가 유지된다.
2. **상황** 비로그인 사용자가 공개 페이지에서 인증이 필요한 기능을 선택했을 때, **동작** `suggestLogin` 모달의 로그인 버튼을 선택하면, **결과** 로그인 페이지(`/login`)로 이동한다.
3. **상황** `suggestLogin` 모달이 표시되었을 때, **동작** 전체 요약 노트 버튼을 선택하면, **결과** 전체 요약 노트 페이지(`/summary`)로 이동한다.
4. **상황** 비로그인 사용자가 보호 페이지에 직접 접근했을 때, **동작** `requireLogin` 모달이 표시되면, **결과** 표시 후 3초 뒤 로그인 페이지(`/login`)로 이동한다.
5. **상황** `requireLogin` 모달에서 3초 전에 닫기를 선택하면, **결과** 남은 타이머가 정리되고 즉시 로그인 페이지(`/login`)로 이동한다.
6. **상황** 로그인 사용자가 회원가입 페이지에 접근했을 때, **동작** `alreadyLoggedIn` 모달이 표시되면, **결과** 표시 후 3초 뒤 메인 페이지(`/`)로 이동한다.
7. **상황** `alreadyLoggedIn` 모달에서 3초 전에 닫기를 선택하면, **결과** 남은 타이머가 정리되고 즉시 메인 페이지(`/`)로 이동한다.

---

### 사용자 스토리 2 - 삭제 확인 및 취소 (우선순위: P2)

작성자는 삭제의 영향을 확인한 뒤 삭제를 승인하거나 아무 변경 없이 취소할 수 있다.

**우선순위 이유**: 되돌리기 어려운 삭제가 실수로 실행되지 않도록 명시적인 확인 절차가 필요하다.

**독립 검증**: `confirmDelete` 모드에서 삭제·취소·닫기를 각각 실행하여 승인과 취소가 구분되고 공통 모달 자체가 데이터를 변경하지 않는지 확인한다.

**인수 시나리오**:

1. **상황** 작성자가 삭제를 선택했을 때, **동작** 삭제 확인 모달에서 `삭제`를 선택하면, **결과** 호출 측에 삭제 승인 동작이 한 번 전달된다.
2. **상황** 삭제 확인 모달이 표시되었을 때, **동작** `취소`를 선택하면, **결과** 삭제 승인 없이 모달이 닫히고 현재 데이터가 유지된다.
3. **상황** 삭제 확인 모달이 표시되었을 때, **동작** 우측 상단 닫기 아이콘을 선택하면, **결과** 취소와 동일하게 삭제 승인 없이 모달이 닫힌다.

---

### 사용자 스토리 3 - 시스템 오류 확인 (우선순위: P3)

사용자는 시스템 요청이 실패했을 때 오류 종류를 이해할 수 있는 안내를 받고, 모달을 닫은 뒤 현재 페이지에서 필요한 다음 행동을 선택한다.

**우선순위 이유**: 기술적인 내부 오류를 노출하지 않으면서 실패한 화면에 사용자가 계속 머무는 상황을 방지해야 한다.

**독립 검증**: 지원하는 각 상태와 네트워크 오류를 전달해 적절한 사용자 문구가 표시되고, 자동 이동 없이 3초 후 닫히며 현재 페이지가 유지되는지 확인한다.

**인수 시나리오**:

1. **상황** 지원하는 시스템 오류 상태가 전달되었을 때, **동작** `error` 모달이 표시되면, **결과** 상태에 맞는 사용자용 오류 문구가 표시된다.
2. **상황** `error` 모달이 열린 상태에서 사용자가 기다리면, **동작** 표시 후 3초가 지나면, **결과** 모달이 자동으로 닫히고 현재 페이지가 유지된다.
3. **상황** `error` 모달에서 닫기 아이콘을 선택하면, **결과** 호출 측의 오류 모달 상태가 종료되고 현재 페이지가 유지된다.
4. **상황** 알 수 없는 상태 또는 상태가 없는 오류가 전달되었을 때, **동작** `error` 모달이 표시되면, **결과** 일반 오류 문구가 표시되고 내부 오류 원문은 노출되지 않는다.

### 예외 상황

- 모달 배경막을 클릭해도 모달이 닫히거나 뒤쪽 페이지 동작이 실행되지 않는다.
- 모달을 닫는 동작은 우측 상단 닫기 아이콘과 모드에 정의된 버튼으로만 허용하며 Escape 입력으로 닫히지 않는다.
- 자동 이동 모드에서 이동 전에 닫기 아이콘을 선택하면 남은 타이머를 정리해 중복 이동을 방지한다.
- 연속해서 여러 표시 요청이 발생해도 한 번에 하나의 공통 모달만 표시한다.
- 상태가 `200`이 아니어도 `201`, `204` 등 성공 범위에 해당하면 오류 모달을 표시하지 않는다.
- 사용자 입력으로 해결할 수 있는 필수값, 형식, 중복, 비밀번호 불일치 등의 검증 오류는 공통 오류 모달 대상에서 제외한다.

## 요구사항 _(필수)_

### 기능 요구사항

- **FR-001**: 시스템은 하나의 공통 모달에서 `mode`에 따라 문구, 버튼 수, 버튼 문구와 허용 동작을 다르게 제공해야 한다.
- **FR-002**: 공통 모달은 제공된 디자인을 기준으로 흰색의 둥근 컨테이너, 우측 상단 Material `close` 아이콘, 프비 메인 이미지, 중앙 정렬 문구와 모드별 버튼을 표시해야 한다.
- **FR-003**: 모달이 열리면 화면의 나머지 영역을 회색 배경막으로 덮고 뒤쪽 페이지의 포인터 상호작용을 차단해야 한다.
- **FR-004**: 배경막 클릭은 모달을 닫거나 뒤쪽 페이지로 전달되어서는 안 된다.
- **FR-005**: Escape 입력은 공통 모달을 닫아서는 안 된다.
- **FR-006**: `preparing` 모드는 준비 중 문구와 닫기 아이콘을 제공하고 닫은 뒤 현재 페이지를 유지해야 한다.
- **FR-007**: `confirmDelete` 모드는 삭제, 취소와 닫기 아이콘을 제공해야 한다.
- **FR-008**: `confirmDelete` 모달은 삭제 선택을 호출 측에 전달하고 직접 데이터를 삭제하거나 서버 요청을 실행해서는 안 된다.
- **FR-009**: `confirmDelete` 모달의 취소와 닫기 아이콘은 삭제 선택을 전달하지 않고 동일한 닫기 결과를 제공해야 한다.
- **FR-010**: `suggestLogin` 모드는 로그인 이동, 전체 요약 노트 이동과 닫기 아이콘을 제공해야 한다.
- **FR-011**: `suggestLogin`의 로그인 버튼은 `/login`, 전체 요약 노트 버튼은 `/summary`로 이동해야 하며 닫기는 현재 페이지를 유지해야 한다.
- **FR-012**: `requireLogin` 모드는 표시 후 3초 뒤 `/login`으로 이동해야 한다.
- **FR-013**: `requireLogin` 모드의 닫기 아이콘은 남은 타이머를 정리하고 즉시 `/login`으로 이동해야 한다.
- **FR-014**: `alreadyLoggedIn` 모드는 표시 후 3초 뒤 `/`로 이동해야 한다.
- **FR-015**: `alreadyLoggedIn` 모드의 닫기 아이콘은 남은 타이머를 정리하고 즉시 `/`로 이동해야 한다.
- **FR-016**: `error` 모드는 오류 상태에 맞는 사용자용 문구를 표시하고 목적지 안내 문구를 추가하지 않아야 한다.
- **FR-017**: `error` 모드는 표시 후 3초 뒤 `onClose`를 호출해 자동으로 닫히며 페이지를 이동하지 않아야 한다.
- **FR-018**: `error` 모드의 닫기 아이콘은 `onClose`를 호출하며, 호출 측에서 별도 이동을 정의하지 않으면 현재 페이지를 유지해야 한다.
- **FR-019**: `error` 모드는 서버의 내부 메시지, 경로, 스택 정보와 민감 정보를 화면에 표시해서는 안 된다.
- **FR-020**: 공통 모달은 성공 범위가 아닌 시스템 응답 상태와 네트워크 오류를 구분해 전달받을 수 있어야 한다.
- **FR-021**: 상태 `401`은 로그인 필요, `403`은 접근 권한 없음, `404`는 요청 내용을 찾을 수 없음, `429`는 요청 과다, `500`은 서버 내부 오류로 안내해야 한다.
- **FR-022**: 상태 `502`, `503`, `504`는 서비스 연결이 원활하지 않은 일시적 오류로 묶어 안내해야 한다.
- **FR-023**: 네트워크 단절은 네트워크 연결 확인 안내를 표시해야 한다.
- **FR-024**: 지원하지 않는 상태 또는 상태가 없는 오류는 일반 오류 문구로 안내해야 한다.
- **FR-025**: 사용자 입력으로 해결할 수 있는 입력 검증 오류는 공통 오류 모달에서 처리해서는 안 된다.
- **FR-026**: 자동 이동 모드는 표시 시점마다 타이머를 하나만 시작하고 모달이 사라지거나 즉시 이동하면 타이머를 정리해야 한다.
- **FR-027**: 하나의 공통 모달이 표시되는 동안 다른 공통 모달이 동시에 겹쳐 표시되어서는 안 된다.
- **FR-028**: 공통 모달은 모드에 필요한 최소 정보만 전달받아야 하며 호출 측에 문구와 고정 이동 경로 입력을 반복해서 요구해서는 안 된다.
- **FR-029**: 공통 모달의 파일명과 컴포넌트명은 `CommonModal.jsx`와 `CommonModal`이어야 한다.

### 오류 상태별 기본 문구

| 전달 상태           | 기본 문구                                      |
| ------------------- | ---------------------------------------------- |
| `401`               | `로그인이 필요합니다.`                         |
| `403`               | `접근 권한이 없습니다.`                        |
| `404`               | `요청한 내용을 찾을 수 없습니다.`              |
| `429`               | `요청이 많습니다. 잠시 후 다시 시도해 주세요.` |
| `500`               | `서버 오류가 발생했습니다.`                    |
| `502`, `503`, `504` | `현재 서비스 연결이 원활하지 않습니다.`        |
| 네트워크 오류       | `네트워크 연결을 확인해 주세요.`               |
| 그 외               | `문제가 발생했습니다.`                         |

모든 `error` 상태는 위 오류 문구만 표시하며 자동 이동 목적지 안내를 덧붙이지 않는다.

### 핵심 엔티티 _(데이터를 다루는 경우에만 작성)_

- **모달 모드**: 표시 목적, 기본 문구, 사용 가능한 버튼과 자동 이동 여부를 결정하는 단일 상태다.
- **모달 공개 상태**: 공통 모달을 현재 화면에 표시할지 결정한다.
- **오류 상태**: `error` 모드의 사용자용 문구를 결정하는 시스템 응답 상태 또는 네트워크 오류 값이다.
- **모달 선택 결과**: 일반 닫기, 삭제 승인 또는 삭제 취소와 같이 호출 측에 전달되는 사용자 행동이다.
- **자동 이동 상태**: 모드별 고정 목적지와 3초 대기 여부를 나타내며 중복 이동을 방지하기 위해 정리되어야 한다.

## 성공 기준 _(필수)_

### 측정 가능한 결과

- **SC-001**: 정의된 6개 모드는 동일한 공통 디자인 안에서 요구된 문구와 버튼 구성을 100% 제공한다.
- **SC-002**: 사용자는 각 수동 조작 모드에서 한 번의 선택으로 닫기, 삭제 승인, 취소 또는 고정 경로 이동을 완료할 수 있다.
- **SC-003**: 삭제 취소 및 닫기 검증 사례의 100%에서 삭제 승인 동작이 발생하지 않고 현재 데이터가 유지된다.
- **SC-004**: `requireLogin`, `alreadyLoggedIn` 모드는 표시 후 3초에 지정된 경로 이동을 한 번만 실행한다.
- **SC-005**: 자동 이동 모드에서 이동 전에 닫기를 선택한 검증 사례의 100%에서 즉시 지정 경로로 한 번 이동하고 예약된 추가 이동은 발생하지 않는다.
- **SC-006**: 지원하는 모든 오류 상태에서 내부 오류 원문과 이동 안내 없이 상태에 맞는 사용자 문구가 표시되며, 3초 후 자동으로 닫히고 현재 페이지가 유지된다.
- **SC-007**: 모달이 표시되는 동안 뒤쪽 페이지로 전달되는 포인터 상호작용은 0건이며 배경막 클릭과 Escape 입력으로 모달이 닫히지 않는다.
- **SC-008**: 두 개 이상의 공통 모달이 동시에 화면에 표시되는 검증 사례는 0건이다.

## 가정

- 모달을 표시할 상황, `mode`, 공개 여부와 오류 상태는 호출 화면에서 제공한다.
- 성공 여부는 단일 `200`이 아니라 성공 응답 범위로 판단하며, 오류 상태 판단과 네트워크 예외 포착은 요청을 실행하는 영역에서 수행한다.
- 실제 삭제 요청은 삭제 대상을 알고 있는 호출 화면이 수행한다.
- `/login`, `/summary`, `/`는 각각 로그인, 전체 요약 노트, 메인 페이지의 고정 경로다.
- 프비 메인 이미지는 모든 모드에서 공통으로 사용한다.
- 현재 한글 이미지 파일명은 유지하며 이 기능에서 파일명을 변경하지 않는다.
- 제공된 디자인은 데스크톱 기준이며 모바일·태블릿 전용 배치는 별도 명세에서 다룬다.
