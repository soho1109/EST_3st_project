# 데이터 모델: 공통 모달

이 기능은 데이터베이스 엔티티를 만들지 않는다. 아래 모델은 컴포넌트 입력과 UI 상태만 정의한다.

## ModalMode

공통 모달이 표시할 내용과 동작을 결정하는 단일 문자열 값이다.

| 값 | 유형 | 문구·행동 |
|---|---|---|
| `preparing` | 수동 닫기 | 준비 중 안내, 현재 페이지 유지 |
| `confirmDelete` | 선택 전달 | 삭제 승인 또는 취소 전달 |
| `suggestLogin` | 선택 이동 | `/login` 또는 `/summary` 이동, 닫으면 현재 페이지 유지 |
| `requireLogin` | 자동 이동 | 3초 후 `/login`, 닫으면 즉시 `/login` |
| `alreadyLoggedIn` | 자동 이동 | 3초 후 `/`, 닫으면 즉시 `/` |
| `error` | 오류 안내·자동 이동 | 상태별 안내, 401은 `/login`, 나머지는 `/` 이동 |

### 검증 규칙

- 한 시점에 정확히 하나의 값만 사용한다.
- `isMode` 같은 복수 Boolean 조합은 사용하지 않는다.
- 허용 목록 밖의 값은 호출 계약 위반이며 임의의 새 모드로 해석하지 않는다.

## ModalVisibility

| 필드 | 형식 | 규칙 |
|---|---|---|
| `isOpen` | Boolean | `true`일 때만 모달을 렌더링한다. |

### 상태 전이

```text
닫힘 -- 호출 측 공개 --> 열림
열림 -- 수동 닫기/취소 --> 닫힘
열림 -- 삭제 승인 --> 호출 측 승인 처리
열림 -- 링크 선택 --> 고정 경로 이동
열림 -- 3초 경과/자동 모드 닫기 --> 고정 경로 이동
```

## ErrorStatus

`mode="error"`에서만 사용하는 선택 입력이다.

| 전달 값 | 사용자 문구 |
|---|---|
| `401` | `로그인이 필요합니다.` |
| `403` | `접근 권한이 없습니다.` |
| `404` | `요청한 내용을 찾을 수 없습니다.` |
| `429` | `요청이 많습니다. 잠시 후 다시 시도해 주세요.` |
| `500` | `서버 오류가 발생했습니다.` |
| `502`, `503`, `504` | `현재 서비스 연결이 원활하지 않습니다.` |
| `network` | `네트워크 연결을 확인해 주세요.` |
| 미지정 또는 그 외 | `문제가 발생했습니다.` |

401 오류 문구에는 `로그인페이지로 이동합니다.`, 나머지 오류 문구에는 `메인페이지로 이동합니다.`가 이어진다. 서버 오류 원문, 스택, 요청 경로는 모델에 포함하지 않는다.

## ModalAction

| 행동 | 결과 |
|---|---|
| `close` | 수동 모드에서는 `onClose`, 자동 모드에서는 고정 경로 즉시 이동 |
| `cancel` | `confirmDelete`에서 삭제 승인 없이 `onClose` |
| `confirm` | `confirmDelete`에서 `onConfirm`을 한 번 호출 |
| `navigate` | 모드가 소유한 고정 경로로 이동 |

## AutoNavigation

| 필드 | 값 | 규칙 |
|---|---|---|
| 지연 | 3000ms | 모달이 열린 시점마다 하나만 예약 |
| 목적지 | `/login` 또는 `/` | `requireLogin`과 오류 401은 `/login`, 나머지 자동 이동은 `/`; 호출자가 주입하지 않음 |
| 정리 | 타이머 해제 | 닫힘, 모드 변경, 언마운트, 즉시 이동 전에 수행 |

## 관계와 책임

- `ModalMode`는 필요한 버튼과 `AutoNavigation` 여부를 결정한다.
- `ErrorStatus`는 `ModalMode`가 `error`일 때만 문구를 결정한다.
- 호출 측은 `ModalVisibility`와 삭제 대상·실제 요청을 소유한다.
- 공통 모달은 `ModalAction`을 전달하거나 고정 이동만 실행하며 데이터를 변경하지 않는다.
