# UI 계약: SignupPage

## 목적

`SignupPage`는 회원가입 화면, 약관·입력 상태와 클라이언트 검증을 제공한다. Header, 실제 인증, 중복 확인과 Loading의 내부 동작은 소유하지 않는다.

## 파일 계약

```text
페이지: src/app/(site)/signup/page.js
스타일: src/app/(site)/signup/page.module.scss
경로: /signup
```

## 공개 입력

- 페이지 컴포넌트는 공개 props를 받지 않는다.
- 실제 인증 서비스나 사용자 상태는 이번 UI 단계에서 주입하지 않는다.

## 렌더링 계약

- Header는 `src/app/(site)/layout.js`가 제공하며 페이지가 직접 렌더링하지 않는다.
- 입력 순서는 닉네임, 이메일, 비밀번호, 비밀번호 확인이다.
- 약관은 전체 동의, 필수 서비스 이용약관, 필수 AI 생성 콘텐츠 이용 안내로 구성한다.
- 로그인 이동은 `Link`와 `/login`을 사용한다.
- 데스크톱 1320px, 태블릿 1024px, 모바일 480px 디자인을 기준으로 반응형 배치를 제공한다.

## 검증 계약

- 최초 진입 시 오류를 표시하지 않는다.
- 입력을 벗어나거나 제출을 시도한 뒤 관련 오류를 표시한다.
- 이메일은 필수와 형식을 검증한다.
- 비밀번호는 영문·숫자·특수문자 포함 및 8~16자를 검증한다.
- 비밀번호 확인은 유효한 비밀번호와 일치해야 한다.
- 오류가 공개된 입력은 접근성 오류 상태와 해당 오류 설명을 연결한다.

## 제출 계약

### UI 우선 단계

- submit 이벤트의 기본 동작을 막고 로컬 오류를 공개한다.
- Supabase, API, 중복 확인, 세션, 이메일 인증, 성공 이동과 Loading을 실행하지 않는다.
- 가짜 성공, 가짜 사용자, 가짜 중복 결과와 테스트용 Promise를 생성하지 않는다.

### 후속 인증 연동 단계

- 닉네임·이메일 중복 확인을 포함한 모든 가입 조건이 통과해야 실제 요청을 허용한다.
- 요청을 소유한 페이지가 Boolean `isLoading`을 관리하고 기존 `<Loading />`을 조건부 표시한다.
- 요청 중 모든 폼 조작과 중복 제출을 차단한다.
- 요청 종료 시 성공·실패와 관계없이 `isLoading`을 해제한다.

## 책임 제외

- Header 렌더링과 펼침·접힘 상태
- Supabase 및 API 계약
- 닉네임·이메일 중복 확인 구현
- 인증 세션 저장과 복구
- 이메일 인증
- 로그인 사용자 판정과 CommonModal
- Suspense fallback과 `loading.js`
- Input·Button 공통 React 컴포넌트
