# 빠른 검증 안내: 회원가입 페이지

## 사전 조건

- Node.js와 프로젝트 의존성이 설치되어 있어야 한다.
- `src/app/(site)/layout.js`에서 공통 Header가 제공되는 현재 구조를 유지한다.
- 회원가입 구현은 [plan.md](./plan.md), [data-model.md](./data-model.md), [SignupPage 계약](./contracts/SignupPage.md)을 따른다.

## 실행

```powershell
npm run dev
```

브라우저에서 `http://localhost:3000/signup`을 연다.

## 검증 시나리오

### 1. 최초 화면

- Header가 페이지 내부에 중복 렌더링되지 않는다.
- 모든 약관과 입력이 비어 있다.
- 오류 문구와 Loading이 표시되지 않는다.
- 입력 순서가 닉네임, 이메일, 비밀번호, 비밀번호 확인이다.

### 2. 약관 관계

- 전체 동의를 선택하면 두 필수 약관이 모두 선택된다.
- 전체 동의를 해제하면 두 필수 약관이 모두 해제된다.
- 개별 약관 하나를 해제하면 전체 동의도 해제된다.
- 두 개별 약관을 직접 선택하면 전체 동의가 선택된다.

### 3. 입력 검증

- 최초 빈 화면에는 오류가 없다.
- 빈 입력을 벗어나면 해당 필수 오류가 표시된다.
- 잘못된 이메일은 형식 오류가 표시된다.
- 비밀번호가 영문·숫자·특수문자를 모두 포함하지 않거나 8~16자를 벗어나면 오류가 표시된다.
- 비밀번호 확인이 다르면 불일치 오류가 표시된다.
- 값을 수정하면 관련 오류가 해제된다.
- 비밀번호와 확인 입력의 표시·숨김이 서로 독립적으로 동작한다.

### 4. UI 단계 경계

- 가입하기를 눌러도 네트워크 요청, 성공 이동, 가짜 Loading 또는 CommonModal이 실행되지 않는다.
- 닉네임·이메일이 임의로 중복 통과 처리되지 않는다.
- `이미 계정이 있습니다.`를 선택하면 `/login`으로 이동한다.

### 5. 반응형

개발자 도구에서 다음 viewport를 각각 확인한다.

- 데스크톱: 1320px
- 태블릿: 1024px
- 모바일: 480px
- 경계 확인: 1025px, 1023px, 481px, 479px

각 화면에서 콘텐츠 잘림, 가로 스크롤, 입력 순서 변경과 조작 불가 요소가 없어야 한다.

### 6. 키보드와 오류 연결

- Tab 키로 약관, 모든 입력, 비밀번호 표시 전환, 가입하기와 로그인 링크에 순서대로 접근할 수 있다.
- 오류가 발생한 입력은 보조기기에 오류 상태와 설명이 연결되며, 검증 전 빈 입력을 오류로 미리 알리지 않는다.
