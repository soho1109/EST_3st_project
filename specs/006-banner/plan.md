# 구현 계획: 공통 광고 배너

**브랜치**: `feature/banner` | **작성일**: 2026-08-09 | **명세**: [`spec.md`](./spec.md)

**입력**: `/specs/006-banner/spec.md`의 기능 명세

## 요약

이미지 전체를 하나의 배너로 표시하고 내부 목적지는 `Link`, 외부 HTTP(S) 목적지는 새 탭 `<a>`로 연결한다. 목적지가 없거나 지원하지 않는 값이면 이미지만 비대화형으로 표시하고, 이미지가 없으면 아무 영역도 만들지 않는다. 배너는 1322:358 원본 비율과 부모 너비 100%만 책임지며 페이지별 크기 유형이나 고정 너비를 갖지 않는다.

## 기술 설계

### 컴포넌트 경계

- `Banner`는 이미지 경로, 대체 설명과 선택 목적지만 받는다.
- 기본 이미지 경로는 `/images/banner.jpg`이며 현재 자산의 1322×358 비율을 사용한다.
- 광고 목적지 선정, 데이터 조회와 페이지별 실제 너비는 호출 영역의 책임이다.
- `Banner`는 이미지 표시, 목적지 유형 구분과 전체 이미지 이동 영역만 책임진다.
- 상태, 이벤트 핸들러와 브라우저 API가 필요하지 않으므로 `"use client"`를 선언하지 않는다.

### 목적지 판별 및 이동

- `/`로 시작하지만 `//`로 시작하지 않는 값은 내부 경로로 취급하고 `Link`로 현재 탭에서 이동한다.
- `http://` 또는 `https://`로 시작하는 절대 주소는 외부 목적지로 취급하고 `<a>`로 새 탭에서 연다.
- 외부 링크에는 새 탭과 원래 페이지의 실행 컨텍스트를 분리하는 관계 속성을 적용한다.
- 빈 문자열, 미지정 값, `//`, `javascript:`, 지원하지 않는 스킴은 이동 가능한 목적지로 취급하지 않는다.
- 목적지가 유효하지 않으면 이미지 요소만 표시하며 링크처럼 보이는 포인터나 키보드 이동 대상으로 만들지 않는다.

### 이미지와 크기

- 정적 자산은 `next/image`로 표시하고 실제 원본 치수 1322×358을 제공한다.
- 이미지와 최상위 배너 영역은 부모의 사용 가능한 너비를 채우고 높이는 자동 계산한다.
- `object-fit: contain` 또는 동등한 비율 유지 방식으로 전체 이미지를 표시하며 고정 높이, 자르기와 강제 늘이기를 사용하지 않는다.
- 메인·학습노트 목록·새 페이지의 너비는 각 부모 컨테이너가 결정한다. `main`, `list` 같은 prop이나 페이지별 클래스는 `Banner`에 추가하지 않는다.
- 별도 CTA·텍스트·아이콘·오버레이를 렌더링하지 않는다.

### 접근성과 실패 상태

- 이동 가능한 배너의 대체 설명은 광고 내용과 이동 목적을 설명해야 한다.
- 이미지 경로가 없거나 명시적으로 비어 있으면 `null`을 반환해 빈 영역과 깨진 이미지를 방지한다.
- 이미지 로드 자체의 네트워크 실패를 위한 대체 UI, 재시도 또는 오류 모달은 이번 범위에 추가하지 않는다.

## 구현 단계

1. `Banner.jsx`에 최소 입력 계약, 이미지 없음 처리와 공통 이미지 렌더링을 구성한다.
2. 내부 경로, 외부 HTTP(S) URL과 유효하지 않은 목적지를 구분해 각각 `Link`, 새 탭 `<a>`, 비대화형 이미지로 렌더링한다.
3. `Banner.module.scss`에서 부모 너비 100%, 자동 높이, 원본 비율과 전체 클릭 영역을 적용한다.
4. `/dev/banner`에 내부·외부·목적지 없음 상태와 서로 다른 세 부모 너비를 구성한다.
5. 명세 시나리오, lint와 build로 검증한다.

구현 단계는 작은 기능 단위로 완료·검증한 뒤 커밋 경계에서 사용자에게 변경 파일과 명령을 안내한다. 사용자가 직접 커밋 완료를 알린 뒤 다음 단계로 진행하며 Codex는 커밋이나 push를 실행하지 않는다.
