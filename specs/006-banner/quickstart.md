# 빠른 시작: 공통 광고 배너 검증

## 사전 조건

- Node.js와 프로젝트 의존성이 설치되어 있다.
- 구현 단계에서 다음 파일만 생성한다.
  - `src/components/Banner.jsx`
  - `src/components/Banner.module.scss`
  - `src/app/(dev)/dev/banner/page.js`
  - `src/app/(dev)/dev/banner/page.module.scss`
- 기존 `src/app/(dev)/dev/page.js`와 제품 페이지는 수정하지 않는다.

## 실행

```powershell
npm run dev
```

브라우저에서 `http://localhost:3000/dev/banner`로 접근한다.

## 개발 확인 페이지 구성

- 내부 목적지, 외부 목적지, 목적지 없음과 미지원 목적지 상태를 구분해 표시한다.
- 같은 배너를 서로 다른 세 부모 너비에 표시한다.
- 부모 컨테이너의 이름과 설명은 배너 바깥에 두고 이미지 내부에는 어떤 요소도 추가하지 않는다.
- 실제 API, 광고 관리, 클릭 통계 또는 회전 배너를 만들지 않는다.

## 수동 검증 시나리오

1. 내부 목적지 배너의 이미지 중앙과 가장자리를 각각 선택해 모두 현재 탭의 같은 내부 경로로 이동하는지 확인한다.
2. 외부 목적지 배너를 선택해 외부 HTTP(S) 주소가 새 탭에서 열리고 원래 개발 페이지가 유지되는지 확인한다.
3. 목적지가 없는 배너와 미지원 목적지 배너가 이미지는 표시하지만 클릭·키보드 이동 대상은 아닌지 확인한다.
4. 이미지 경로를 명시적으로 비운 사례에서 깨진 이미지와 빈 배너 영역이 나타나지 않는지 확인한다.
5. 서로 다른 세 부모 너비에서 이미지 전체가 너비를 채우고 1322:358 비율을 유지하며 잘림과 왜곡이 없는지 확인한다.
6. 이미지 밖이나 위에 별도 CTA 버튼, 문구, 아이콘 또는 오버레이가 없는지 확인한다.
7. `Banner`에 `main`, `list` 같은 크기 유형 없이 부모 너비만으로 모든 사례가 표시되는지 확인한다.

## 정적 검증

```powershell
npm run lint
npm run build
```

두 명령 모두 오류 없이 종료되고 `/dev/banner`가 build 결과에 포함되어야 한다.

## 범위 확인

- 제품 페이지, 기존 `/dev/page.js`, 이미지 파일명을 수정하지 않는다.
- 새 패키지, API, 서버 통신, 광고 관리와 클릭 통계 코드가 없어야 한다.
- 배너 컴포넌트에 페이지별 고정 너비나 크기 유형이 없어야 한다.
