# 조사 결과: 공통 광고 배너

## 결정 1: 내부와 외부 목적지 구분

**결정**: 내부 경로는 `Link`, 외부 HTTP(S) URL은 새 탭 `<a>`를 사용한다.

**근거**: 프로젝트 규칙은 정적 내부 이동에 `Link`를 우선하며, 외부 사이트는 일반 문서 이동과 새 탭 의미를 갖는 앵커가 적합하다.

**검토한 대안**: 모든 목적지를 `<a>`로 처리하면 내부 이동에서 앱 전환 이점을 잃고, 모든 목적지를 `Link`로 처리하면 외부 이동 의도와 새 탭 계약이 불명확해져 제외한다.

## 결정 2: 목적지 허용 범위

**결정**: `/`로 시작하는 상대 내부 경로와 `http://`, `https://` 절대 외부 주소만 이동 가능하게 한다. `//`, `javascript:`와 기타 스킴은 비대화형 이미지로 처리한다.

**근거**: 이번 배너 요구는 사이트 내부 페이지와 외부 광고 웹 페이지다. 지원 범위를 명시하면 잘못된 값으로 빈 탭이나 예상하지 못한 동작이 발생하는 것을 막을 수 있다.

**검토한 대안**: 모든 문자열을 그대로 링크로 사용하면 유효하지 않거나 의도하지 않은 스킴도 이동 대상으로 해석될 수 있어 제외한다.

## 결정 3: 서버 컴포넌트 유지

**결정**: `Banner.jsx`에 `"use client"`를 추가하지 않는다.

**근거**: 이미지와 링크 렌더링에는 React 상태, 이벤트 핸들러 또는 브라우저 API가 필요하지 않다. App Router의 기본 서버 컴포넌트로 충분하다.

**검토한 대안**: 단순 링크를 위해 Client Component로 전환하는 것은 클라이언트 경계를 불필요하게 넓혀 제외한다.

## 결정 4: 부모 너비와 원본 비율

**결정**: 공통 배너는 부모 너비 100%와 자동 높이를 사용하고, 페이지별 최대 너비는 부모 컨테이너가 소유한다. 정적 이미지 원본 치수 1322×358을 사용한다.

**근거**: `next/image`에 원본 너비와 높이를 제공하면 이미지의 종횡비 공간을 확보할 수 있고, CSS로 표시 너비를 유연하게 바꾸면서 높이를 자동 계산할 수 있다.

**검토한 대안**: `main`, `list` 크기 유형은 사용처가 늘 때마다 공통 컴포넌트 변경이 필요하고, 고정 너비·높이는 두 디자인을 동시에 만족하지 못해 제외한다.

## 결정 5: 누락 값 처리

**결정**: 이미지 경로가 없으면 아무것도 렌더링하지 않는다. 이미지는 있지만 목적지가 없거나 유효하지 않으면 같은 이미지를 링크 없이 표시한다.

**근거**: 깨진 이미지와 빈 컨테이너는 피하면서, 이미 준비된 광고 이미지는 정보로 표시할 수 있고 잘못된 이동만 차단한다.

**검토한 대안**: 목적지가 없을 때 배너 전체를 숨기면 기존 명세의 “이동 가능한 배너로 취급하지 않는다”보다 강한 동작이 되고, 임의의 기본 목적지를 넣으면 사용자 결정을 위반하므로 제외한다.

## 결정 6: 이미지 대체 설명

**결정**: 배너의 광고 내용과 이동 목적을 설명하는 대체 설명을 호출 영역에서 제공한다.

**근거**: 클릭 가능한 이미지의 의미가 시각 정보에만 의존하지 않아야 하며, 향후 이미지가 바뀌면 설명도 함께 바뀌어야 한다.

**검토한 대안**: 고정된 빈 대체 설명은 이동 링크의 목적을 전달하지 못하고, 파일명 자동 사용은 사용자에게 유용한 설명이 아니므로 제외한다.
